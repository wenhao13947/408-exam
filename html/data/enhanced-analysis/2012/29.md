## 答案

选 **B. 260ms**。

## 解析

这道题的求解方法是明确的：用甘特图分析 **CPU 与 I/O 是否能并行**。结合图示，可顺着时间轴看两个作业对 CPU 和 I/O 设备的占用关系。

**图解：作业执行甘特图**

观察时间轴上 P1、P2 对 CPU 与 I/O 的交替占用关系。

![作业执行甘特图](/data/enhanced-analysis/assets/2012/29/original-analysis-1.svg)

已知：

- `P1`：计算 `60ms`，I/O `80ms`，计算 `20ms`
- `P2`：比 `P1` 晚到 `5ms`，其流程为：计算 `120ms`，I/O `40ms`，计算 `40ms`

在多道批处理系统中，某作业做 I/O 时，CPU 可以转去执行另一个已就绪作业。因此最自然、也最优的排程是让 CPU 尽量不空闲。

按题面可直接排出如下时间线：

| 时间段 | CPU 执行 | I/O 执行 |
|---|---|---|
| `0~60` | `P1` 计算 `60ms` | 空闲 |
| `60~140` | `P2` 计算 | `P1` I/O `80ms` |
| `140~180` | `P2` 继续计算 | 空闲；`P1` 等待 CPU |
| `180~200` | `P1` 计算 `20ms` | `P2` I/O `40ms` |
| `200~220` | 空闲 | `P2` 继续 I/O |
| `220~260` | `P2` 最后计算 `40ms` | 空闲 |

若严格按上表推进，总完成时刻是 **`260ms`**。这正好对应标准答案 **B**。

这里也可以逐步核对：

1. `P1` 先到，必须先运行其第一段计算：`0~60`
2. `P1` 转入 I/O：`60~140`
3. `P2` 的第一段计算从 `60ms` 连续执行到 `180ms`
4. `P1` 虽在 `140ms` 完成 I/O，但要等待 CPU；`180~200ms` 完成最后 `20ms` 计算
5. `P2` 在 `180~220ms` 执行 I/O，随后在 `220~260ms` 完成最后 `40ms` 计算

因此两个作业全部完成的最早时刻是 **260ms**。

## 选项分析

### A. 240ms

不对。

若按题面中的“计算 - I/O - 计算”顺序分析，`P2` 至少要经历：

- 第一段计算
- 一次 I/O
- 最后一段计算

`P2` 最早只能从 `60ms` 开始其第一段计算，之后还要完成 `40ms` I/O 和 `40ms` 计算，故最早完成时刻为 `260ms`，不能选 `240ms`。

### B. 260ms

这是标准答案。

本题考点是多道批处理系统中 **CPU 与 I/O 的并行执行**，应通过甘特图判断总完成时刻。结合标准答案，本题应选 **260ms**。

### C. 340ms

不对。

`340ms` 明显偏大。因为如果完全不利用并行，两个作业串行执行总时间才是：

$$
(60+80+20)+(120+40+40)=160+200=360ms
$$

而多道批处理系统恰恰允许一个作业做 I/O 时，另一个作业占用 CPU，所以总时间一定 **小于 360ms**。`340ms` 虽比 `360ms` 小，但仍没有体现出题目要求下应有的并行效果，因此不是最少时间。

### D. 360ms

不对。

`360ms` 是把两个作业完全串行、且几乎不发生 CPU 与 I/O 重叠时才会出现的总时长：

$$
P1: 60+80+20=160ms
$$

$$
P2: 120+40+40=200ms
$$

$$
160+200=360ms
$$

这与“多道批处理系统”下 CPU 和 I/O 可以并行工作的条件不符，所以不是最少时间。

## 易错点

1. **把多道批处理当成单道执行**
   
   若认为 `P1` 做 I/O 时 CPU 也必须等待，就会把时间算大，甚至直接算成 `360ms`。

2. **机械采用视频转写中的错误数值**
   
   转写里出现了“226ms”，这既不在选项中，也与题面条件不一致，应判定为口误或识别错误，不能作为结论。

3. **在 `140ms` 时抢占 P2**
   
   `P1` 完成 I/O 后进入就绪状态，但不能直接打断正在执行第一段计算的 `P2`；否则会得到错误的时间线。
