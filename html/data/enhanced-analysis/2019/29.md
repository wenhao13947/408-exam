## 答案
C. `5`

## 解析
题目采用 `LRU` 页面置换算法和局部置换策略，进程 `P` 预分配 `4` 个页框，访问序列为：

`0, 1, 2, 7, 0, 5, 3, 5, 0, 2, 7, 6`

要求的是**产生页置换的总次数**，不是缺页次数。

前 `4` 次访问 `0、1、2、7` 时，页框由空变满，只发生缺页，**不构成置换**。  
从第 `5` 次访问开始，页框已满，后续每次缺页才可能引发置换。

具体过程如下：

- 访问 `0`：已在内存中，不缺页。
- 访问 `5`：不在内存中，且页框已满，发生置换。  
  按 `LRU`，最近使用情况中 `1` 最久未被访问，淘汰 `1`，换入 `5`。置换次数 `+1`。
- 访问 `3`：不在内存中，发生置换。  
  此时 `2` 最久未被访问，淘汰 `2`，换入 `3`。置换次数 `+1`。
- 访问 `5`：已在内存中，不缺页。
- 访问 `0`：已在内存中，不缺页。
- 访问 `2`：不在内存中，发生置换。  
  此时 `7` 最久未被访问，淘汰 `7`，换入 `2`。置换次数 `+1`。
- 访问 `7`：不在内存中，发生置换。  
  此时 `3` 最久未被访问，淘汰 `3`，换入 `7`。置换次数 `+1`。
- 访问 `6`：不在内存中，发生置换。  
  此时 `5` 最久未被访问，淘汰 `5`，换入 `6`。置换次数 `+1`。

因此，页置换总次数为 `5` 次。

## 选项分析
- A. `3`：少算了后续几次在页框已满情况下发生的置换。
- B. `4`：少算了一次置换。
- C. `5`：正确。
- D. `6`：多算了置换次数，题目中实际只有 `5` 次。

## 易错点
本题最容易把“缺页次数”和“页置换次数”混为一谈。前 `4` 次访问虽然都缺页，但因为页框未满，只是装入页面，不算置换。只有在页框已满后，缺页并换出旧页，才计入页置换次数。
