## 答案

选 **A. 仅Ⅰ、Ⅱ**。

Ⅰ正确，Ⅱ正确，Ⅲ错误。

## 解析

本题考查的是用户进程执行 `read` 系统调用读取磁盘文件时，进程状态变化、CPU 运行态切换，以及文件操作接口参数的含义。

先看整体过程：用户进程发出 `read` 请求后，CPU 需要从用户态进入核心态，由内核执行文件读操作；如果所需文件数据此时还不在内存中，就要等待磁盘 I/O 完成，在等待期间该进程进入阻塞（睡眠等待）状态。另一方面，`read` 是对“已经打开”的文件进行读取，因此它依靠的是文件描述符，而不是文件名。

### 对Ⅰ的判断

Ⅰ说：“若该文件的数据不在内存中，则该进程进入睡眠等待状态。”

这个说法正确。

因为题目讨论的是从磁盘文件读数据。若所需数据尚未在内存中，内核就必须先把相关数据从外存调入内存。在这段等待 I/O 完成的时间内，请求该操作的进程不能继续向下执行，会进入阻塞态，也可表述为睡眠等待状态；等数据调入完成后，再被唤醒继续执行。

这里更关键的结论是：**进程会因等待外存 I/O 而阻塞**。本题判定只需抓住这一点即可。

### 对Ⅱ的判断

Ⅱ说：“请求 `read` 系统调用会导致 CPU 从用户态切换到核心态。”

这个说法正确。

`read` 属于系统调用。用户程序本来运行在用户态，而系统调用需要内核提供服务，因此发起 `read` 时会通过陷入机制进入操作系统内核，CPU 由用户态切换到核心态，执行相应的内核代码；完成后再返回用户态。

所以Ⅱ成立。

### 对Ⅲ的判断

Ⅲ说：“`read` 系统调用的参数应包含文件的名称。”

这个说法错误。

文件名或路径名是在 `open` 阶段使用的。一个文件被 `open` 打开后，内核返回该文件对应的**文件描述符**，后续 `read`、`write` 等操作都是通过这个文件描述符来定位已打开文件，而不是再次传入文件名。

`read` 的典型参数是：

- 文件描述符 `fd`
- 用户缓冲区首地址 `buf`
- 请求读取的字节数 `n`

因此，Ⅲ把 `open` 的参数要求误套到了 `read` 上，结论错误。

## 选项分析

### A. 仅Ⅰ、Ⅱ

正确。

- Ⅰ正确：文件数据不在内存时，需要等待磁盘 I/O，进程进入阻塞/睡眠等待状态。
- Ⅱ正确：`read` 是系统调用，会使 CPU 从用户态切换到核心态。
- 因而 A 符合题意。

### B. 仅Ⅰ、Ⅲ

错误。

- Ⅰ正确；
- 但Ⅲ错误，因为 `read` 使用的是文件描述符，不要求参数中包含文件名。
- 所以 B 错。

### C. 仅Ⅱ、Ⅲ

错误。

- Ⅱ正确；
- 但Ⅲ错误，原因同上：文件名属于 `open` 阶段的信息，不是 `read` 的必需参数。
- 所以 C 错。

### D. Ⅰ、Ⅱ和Ⅲ

错误。

- Ⅰ、Ⅱ都正确；
- Ⅲ错误，因此“三项都对”不成立。
- 所以 D 错。

## 易错点

1. 容易把 `open` 和 `read` 混在一起。  
`open` 需要文件名或路径名；`read` 面向的是“已打开文件”，依靠文件描述符工作。

2. 容易只记住“系统调用由内核完成”，却忽略“态切换”。  
只要是系统调用，就涉及从用户态进入核心态执行内核服务，Ⅱ因此必对。

3. 容易把“等待文件读入”理解成 CPU 一直给该进程执行。  
实际上，等待外存 I/O 时，请求该 I/O 的进程会阻塞，不会持续占用 CPU。

因此，本题应选 **A**。
