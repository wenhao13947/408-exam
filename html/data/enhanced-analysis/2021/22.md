## 答案

A。  
错误原因在于：在多重中断系统中，CPU 并非只能在用户态检测和响应中断；当 CPU 处于内核态执行中断服务程序时，仍可能响应更高优先级的中断。

## 解析

题干考查的是多重中断系统中 CPU 响应中断的基本条件与过程。对这类题，默认讨论普通可屏蔽中断；若题目未特别说明，一般不把不可屏蔽中断作为判断依据。

CPU 响应一次中断，通常要同时满足以下三个条件：

- CPU 处于开中断状态
- 当前指令已经执行结束
- 检测到未被屏蔽的中断请求信号

只有这三个条件同时成立，CPU 才会进入中断响应周期。

本题的关键在于区分“用户态/内核态”和“是否允许响应更高优先级中断”：

- 用户程序运行时，CPU 可以在合适时机检测并响应中断。
- 中断服务程序在内核态执行，但这不意味着内核态一定不能再响应中断。
- 在多重中断系统中，如果 CPU 正在内核态处理某个中断，此时到来一个更高优先级且未被屏蔽的中断，在满足开中断等条件时，CPU 仍可以检测并响应这个新中断，这正是中断嵌套得以实现的基础。

因此，A 把“能否检测和响应中断”错误地限定在“仅用户态”，结论显然过窄，所以 A 错。

## 选项分析

A. 仅在用户态（执行用户程序）下，CPU 才能检测和响应中断  
错误。  
多重中断允许中断嵌套。CPU 在内核态处理中断时，若来了更高优先级的中断，仍可能继续响应。若只能在用户态响应中断，就无法实现多重中断。

B. CPU 只有在检测到中断请求信号后，才会进入中断响应周期  
正确。  
进入中断响应周期的前提之一就是检测到中断请求信号。对普通可屏蔽中断而言，CPU 通常是在当前指令执行结束后进行中断检测；检测到信号后，才可能进入响应阶段。

C. 进入中断响应周期时，CPU 一定处于中断允许（开中断）状态  
正确。  
“开中断”本身就是 CPU 响应中断的必要条件之一。既然已经进入中断响应周期，说明响应条件已满足，因此 CPU 此时必然处于中断允许状态。

D. 若 CPU 检测到中断请求信号，则一定存在未被屏蔽的中断源请求信号  
正确。  
若某中断请求已被屏蔽，则对 CPU 而言它不构成可检测、可响应的有效中断请求。反过来说，只要 CPU 检测到了中断请求信号，就说明至少存在一个未被屏蔽的中断源请求信号。

## 易错点

- 不要把“中断服务程序在内核态执行”误解成“内核态不能响应中断”。在多重中断中，内核态也可能响应更高优先级中断。
- 要区分“检测到中断请求”与“进入中断响应周期”。后者以前者为前提，且还要求当前指令执行完毕、CPU 处于开中断状态。
- 题目若未特别说明，一般按普通可屏蔽中断处理，不用拿不可屏蔽中断来否定常规结论。
