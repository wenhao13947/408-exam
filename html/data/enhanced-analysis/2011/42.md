## 答案

设两个等长升序序列当前保留区间的中位数分别为 $a$ 和 $b$。

### （1）

基本设计思想如下：

1. 分别取当前序列 $A$、$B$ 的中位数 $a$、$b$。
2. 若 $a=b$，则该值就是两个序列合并后的中位数。
3. 若 $a<b$，则合并后的中位数不可能落在 $A$ 的较小一半，也不可能落在 $B$ 的较大一半，因此同时舍弃这两部分，并保证两边舍弃的元素个数相等。
4. 若 $a>b$，则对称地舍弃 $A$ 的较大一半和 $B$ 的较小一半，仍保证两边舍弃的元素个数相等。
5. 在缩小后的两个等长有序子区间中重复上述过程，直到两个区间都只剩 1 个元素，此时返回两者中较小者。

### （2）

可按上述思想写出如下 C 语言实现：

```c
int M_Search(int A[], int B[], int n) {
    int s1 = 0, d1 = n - 1;   // A 当前区间为 A[s1...d1]
    int s2 = 0, d2 = n - 1;   // B 当前区间为 B[s2...d2]
    int m1, m2;

    while (s1 != d1 || s2 != d2) {
        m1 = (s1 + d1) / 2;
        m2 = (s2 + d2) / 2;

        if (A[m1] == B[m2])
            return A[m1];

        if (A[m1] < B[m2]) {
            // 当前区间长度为奇数，保留 A[m1] 和 B[m2]
            if ((d1 - s1 + 1) % 2 == 1) {
                s1 = m1;
                d2 = m2;
            }
            // 当前区间长度为偶数，舍弃 A[m1]，保留 B[m2]
            else {
                s1 = m1 + 1;
                d2 = m2;
            }
        } else {
            // A[m1] > B[m2]
            // 当前区间长度为奇数，保留 A[m1] 和 B[m2]
            if ((d1 - s1 + 1) % 2 == 1) {
                d1 = m1;
                s2 = m2;
            }
            // 当前区间长度为偶数，保留 A[m1]，舍弃 B[m2]
            else {
                d1 = m1;
                s2 = m2 + 1;
            }
        }
    }

    return A[s1] < B[s2] ? A[s1] : B[s2];
}
```

### （3）

时间复杂度为 $O(\log n)$，空间复杂度为 $O(1)$。

## 解析

### 解法一：暴力法

把两个升序序列按归并排序的方式合并，只需归并到第 $n$ 个元素即可得到中位数。时间复杂度为 $O(n)$；若保存完整合并结果，空间复杂度为 $O(n)$，只用计数器时可降为 $O(1)$。该方法正确且容易写，但没有充分利用“两个序列都有序且等长”的条件。

### 解法二：优化解法

比较两个当前区间的中位数，每轮排除不可能包含最终中位数的等量部分，将时间复杂度降为 $O(\log n)$。

> **考场建议：** 先确保能写出归并法，再尝试从“两边等量删除”推出二分缩减；不要为了追求最优而把正确的基础算法也丢掉。

### （1）

题目要求找的是两个等长升序序列合并后的中位数。直接归并后再取中位数当然可行，但那样时间和空间都不够高效，不符合本题“尽可能高效”的要求。

更合适的做法是利用两个序列本身有序这一条件，同步缩小搜索区间。

设当前两个等长区间的中位数分别为 $a$ 和 $b$。

1. 若 $a=b$

那么这个值就是合并后序列的中位数。因为在两个有序区间中，位于 $a$ 左边的元素个数与位于 $b$ 右边的元素个数正好形成对称，而当 $a=b$ 时，这个值已经处在合并后序列的中间位置。

2. 若 $a<b$

则合并后的中位数不可能在 $A$ 的较小一半中，也不可能在 $B$ 的较大一半中。

原因是：

- $A$ 中位数左侧那部分元素都不大于 $a$；
- $B$ 中位数右侧那部分元素都不小于 $b$；
- 既然 $a<b$，那么真正的合并中位数只能落在中间那一段可能范围内。

因此可以同时舍弃：

- $A$ 的较小一半；
- $B$ 的较大一半。

并且两边舍弃元素数必须相等，这样才能保证合并后“中间位置”的相对编号不变。

3. 若 $a>b$

处理完全对称：同时舍弃

- $A$ 的较大一半；
- $B$ 的较小一半；

且两边舍弃长度相等。

4. 重复上述过程

每一轮都把候选区间缩小到原来的一半左右，直到两个区间都只剩 1 个元素。此时合并后前面的那个元素就是中位数，因此返回两者中较小者。

### （2）

第（2）问的代码就是把第（1）问的“同步缩小区间”思想落实为边界更新。

可用四个下标表示当前搜索区间：

- $A[s1...d1]$
- $B[s2...d2]$

每轮取其中点：

$$
m1=\left\lfloor \frac{s1+d1}{2}\right\rfloor,\quad
m2=\left\lfloor \frac{s2+d2}{2}\right\rfloor
$$

然后比较 $A[m1]$ 与 $B[m2]$。

#### 当 $A[m1] < B[m2]$ 时

保留 $A$ 的后半段和 $B$ 的前半段。

这里要注意区间长度的奇偶性，因为题目把中位数定义为第 $\lceil L/2 \rceil$ 个元素，长度为奇数和偶数时，中点是否应被舍弃并不相同。

- 若当前长度为奇数，则保留 $A[m1]$、$B[m2]$：
  $$
  s1=m1,\quad d2=m2
  $$
- 若当前长度为偶数，则舍弃 $A[m1]$，保留 $B[m2]$：
  $$
  s1=m1+1,\quad d2=m2
  $$

#### 当 $A[m1] > B[m2]$ 时

做对称处理，保留 $A$ 的前半段和 $B$ 的后半段。

- 若当前长度为奇数，则保留 $A[m1]$、$B[m2]$：
  $$
  d1=m1,\quad s2=m2
  $$
- 若当前长度为偶数，则保留 $A[m1]$，舍弃 $B[m2]$：
  $$
  d1=m1,\quad s2=m2+1
  $$

#### 终止条件

当两个区间都缩小为单个元素时，即

$$
s1=d1,\quad s2=d2
$$

此时答案就是

$$
\min(A[s1],\,B[s2])
$$

因为两个单元素分别是各自剩余候选中的最小上界，合并后排在前面的那个就是总中位数。

### （3）

由第（1）问和第（2）问可知，每轮比较后都会把候选区间长度缩小到原来的一半左右，因此有

$$
T(n)=T(n/2)+O(1)
$$

故时间复杂度为

$$
O(\log n)
$$

算法中只使用了若干个下标变量和中间变量，没有申请与 $n$ 相关的额外存储空间，所以空间复杂度为

$$
O(1)
$$

每轮都将两个候选区间近似减半，因此时间复杂度为 $O(\log n)$。

## 易错点

1. 不能把本题写成“先归并再找中位数”作为主算法。那样能做出结果，但不符合本题对效率的要求。
2. 舍弃两边区间时，必须保证舍弃的元素个数相等，否则会破坏合并后中位数的位置关系。
3. 偶数长度与奇数长度时，中点是否保留不同，边界更新很容易错一位。
4. 两个序列的起始下标都应初始化为 `0`，即 `s1 = 0`、`s2 = 0`。
5. 该算法的时间复杂度为 $O(\log n)$，空间复杂度为 $O(1)$。
