## 答案

### （1）
题 45(a) 图中有两处错误：

- 进入区语句 `if (key == TRUE) swap key, lock` 应改为 `while (key == TRUE) swap key, lock`
- 退出区语句 `lock = TRUE` 应改为 `lock = FALSE`

### （2）
不可以用函数调用语句 `newSwap(&key, &lock)` 代替指令 `swap key, lock` 来实现临界区互斥。原因是 `swap key, lock` 依赖的是对共享变量 `lock` 的原子交换，而 `newSwap()` 是普通函数，并发执行时不能保证交换过程的原子性，可能导致多个线程同时进入临界区。

## 解析

题干已说明：`lock = TRUE` 表示线程不能进入临界区，`lock = FALSE` 表示线程能够进入临界区。其中，`lock` 是线程共享变量，`key` 是线程的局部变量。

### （1）

先看进入区。

线程进入区时，先令 `key = TRUE`，再执行 `swap key, lock`。该交换操作的作用是：把共享变量 `lock` 的当前值送入本线程的 `key`，同时把 `lock` 置为 `TRUE`。

因此：

- 若原来 `lock = FALSE`，交换后 `key = FALSE`，说明原先锁空闲，该线程可进入临界区；
- 若原来 `lock = TRUE`，交换后 `key = TRUE`，说明锁已被占用，该线程不能进入临界区。

由此可见，线程在锁被占用时应反复执行交换，直到某次交换后得到 `key = FALSE` 为止，所以这里必须使用循环判断，而不能只判断一次。

因此，进入区中的错误语句
`if (key == TRUE) swap key, lock`
应改为
`while (key == TRUE) swap key, lock`

再看退出区。

线程退出临界区时，应释放锁。根据题干语义，只有 `lock = FALSE` 时其他线程才能进入临界区，所以退出区应将 `lock` 置为 `FALSE`。

因此，退出区中的错误语句
`lock = TRUE`
应改为
`lock = FALSE`

### （2）

本问是在第（1）问基础上进一步判断：进入区中使用的 `swap key, lock`，能否用普通函数 `newSwap(&key, &lock)` 来代替。

答案是不可以。

原因在于，`swap key, lock` 是一条交换指令，它要求对共享变量 `lock` 的交换操作是原子的，即“读出旧值并写入新值”作为一个不可分割的整体完成。只有这样，多个线程竞争进入临界区时，才能保证同一时刻只有一个线程获得锁。

而 `newSwap()` 是普通函数，其代码本质上分为多步：
先把 `*a` 保存到临时变量，再把 `*b` 赋给 `*a`，最后把临时变量赋给 `*b`。由于 `lock` 是共享变量，多个线程可以并发执行 `newSwap(&key, &lock)`，执行过程中可能发生线程切换，从而使这些读写步骤交叉进行，不能保证对 `lock` 的原子交换。

这样就可能出现多个线程都认为自己获得了锁，随后同时进入临界区，破坏互斥。

所以，虽然 `newSwap()` 在功能上也能交换两个变量的值，但它不具备 `swap` 指令所要求的原子性，不能代替 `swap key, lock` 实现临界区互斥。

## 易错点

- 要区分 `key` 和 `lock`：`key` 是线程局部变量，`lock` 才是共享锁变量。
- 本题判断 `newSwap()` 是否可替代 `swap`，关键不在于“能否交换两个值”，而在于“能否原子地交换共享变量”。
- `if` 改为 `while` 的原因是线程需要循环等待锁释放，不能只检测一次。
- 退出区必须释放锁，因此应令 `lock = FALSE`，不能写成 `lock = TRUE`。
