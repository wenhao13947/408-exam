## 答案

B。正确处理流程应为：用户程序先通过系统调用进入设备无关软件层，再由设备驱动程序执行具体设备操作，最后由中断处理程序在 I/O 完成时进行后续处理。

## 解析

本题考查的是操作系统中 I/O 软件的层次结构，以及用户发出一次磁盘 I/O 请求后的处理次序。

磁盘 I/O 请求不是由用户程序直接操作硬件完成的，而是要按操作系统的分层结构自上而下处理。核心顺序如下：

用户程序 → 系统调用处理程序 → 设备驱动程序 → 中断处理程序

判断依据如下。

首先，用户程序发出 I/O 请求时，通常并不直接和磁盘控制器打交道，而是通过库函数或系统调用进入操作系统内核。因此第一步之后应当到达的是**系统调用处理程序**。这一层本质上属于设备无关软件层，负责接收上层请求，并完成诸如逻辑设备名到物理设备的映射、设备分配、回收与保护等通用管理工作。

然后，请求会交给**设备驱动程序**。因为真正“怎么对磁盘发命令、如何启动控制器、如何把抽象的读写请求翻译成硬件可执行操作”，这些都属于驱动程序的职责。也就是说，系统调用处理程序负责“提出规范化请求”，设备驱动程序负责“把请求落实到具体硬件”。

最后，当磁盘完成数据传输或设备状态发生变化时，设备会发出**中断**。这时由**中断处理程序**接管，保存现场、唤醒因等待 I/O 而阻塞的进程，并完成本次 I/O 结束后的收尾工作。因此中断处理程序应当出现在驱动程序之后，而不是之前。

所以正确顺序只能是 B。

## 选项分析

A．用户程序 → 系统调用处理程序 → 中断处理程序 → 设备驱动程序

错误。中断处理程序是在设备完成操作、发出中断后才介入的，不可能先于设备驱动程序执行。驱动程序必须先启动设备，之后才可能发生中断。

B．用户程序 → 系统调用处理程序 → 设备驱动程序 → 中断处理程序

正确。该顺序符合 I/O 请求从上层软件到底层硬件、再由中断机制完成善后的标准流程。

C．用户程序 → 设备驱动程序 → 系统调用处理程序 → 中断处理程序

错误。用户程序不能越过系统调用处理程序直接进入设备驱动程序。驱动程序属于内核中的底层设备控制部分，必须先由系统调用进入内核并完成统一管理。

D．用户程序 → 设备驱动程序 → 中断处理程序 → 系统调用处理程序

错误。既错在“用户程序直接到驱动程序”，也错在“系统调用处理程序排在最后”。系统调用处理程序应当是用户请求进入内核后的前置环节，不是 I/O 完成后的末端环节。

## 易错点

容易把“中断处理程序”误认为是发出 I/O 请求时立即参与的模块。实际上，中断处理程序主要是在设备完成操作后响应中断，用于现场保护、进程唤醒和结果收尾。

还要区分“系统调用处理程序”和“设备驱动程序”的职责：前者负责设备无关的统一管理，后者负责与具体硬件相关的控制命令。只要抓住这一点，顺序就不会混淆。
