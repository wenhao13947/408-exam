## 答案

C。`x += 1` 与 `x += 2` 需要互斥执行，因为二者会并发读写同一个共享变量 `x`，若不互斥会发生竞争，导致最终结果不确定。

## 解析

判断“是否需要互斥”，核心看两点：

- 两个操作是否访问同一个临界资源；
- 不同执行次序是否会因并发交叉而破坏结果正确性。

本题中，`P1` 和 `P2` 是两个不同进程。不同进程通常拥有各自独立的地址空间，因此 `P1` 中的 `x` 与 `P2` 中的 `x` 不是同一个变量，不能因为名字相同就视为同一资源。

同理，两个线程代码块中若各自定义了局部变量 `a`，即使变量名相同，也分别属于不同函数或不同栈帧，对应不同存储单元，不是共享资源。

因此，只有当两个并发操作确实作用于同一个共享变量时，才需要进一步判断是否必须互斥。

对 `x += 1`、`x += 2` 而言，表面上各是一条高级语言语句，但实际执行时通常不是原子操作，而会分解为“读-改-写”三个步骤。可抽象为：

对于 `x += 1`：
$$
R_1 \leftarrow x,\quad R_1 \leftarrow R_1 + 1,\quad x \leftarrow R_1
$$

对于 `x += 2`：
$$
R_2 \leftarrow x,\quad R_2 \leftarrow R_2 + 2,\quad x \leftarrow R_2
$$

若初值 `x = 0`，可能出现如下交叉执行：

- 线程 1 先读出 `x=0` 到 `R_1`
- 线程 2 再读出 `x=0` 到 `R_2`
- 线程 1 写回 `1`
- 线程 2 写回 `2`

最终结果变成 `x=2`，而不是串行执行下应有的 `x=3`。这说明并发交叉会造成“丢失更新”，结果不确定。

若对该共享变量加锁实现互斥，则 `x += 1` 与 `x += 2` 只能整体串行执行，执行次序虽然仍可能不同，但最终结果都为：
$$
x = 0 + 1 + 2 = 3
$$

所以，本题只有 `x += 1` 与 `x += 2` 需要互斥。

## 选项分析

A. `a = 1` 与 `a = 2`  
错误。这里的两个 `a` 并不是同一个共享变量，而是不同线程中的局部变量。变量名相同不代表共享同一存储单元，因此不构成临界资源竞争，不需要互斥。

B. `a = x` 与 `b = x`  
错误。两者虽然可能都读取同一个 `x`，但本质上是读操作及结果先后关系问题。若题目关注的是让 `a`、`b` 取得某种确定先后对应的值，需要的是同步关系约束，而不是互斥本身。仅靠互斥不能保证题目所需的先后次序，因此该项不是“需要互斥执行”的正确答案。

C. `x += 1` 与 `x += 2`  
正确。两者对同一个共享变量 `x` 做修改，且修改操作不是原子的，会发生读写竞争；不互斥会导致最终结果不确定，因此必须互斥执行。

D. `x += 1` 与 `x += 3`  
错误。它们分别位于不同进程 `P1`、`P2` 中，而两个进程的地址空间独立，因此这里的两个 `x` 不是同一个变量，不是同一个临界资源，不需要互斥。

## 易错点

- 不要因为变量名相同，就误判为同一个变量。是否共享，取决于作用域和地址空间，而不是名字。
- “需要互斥”与“需要同步”不是一回事。  
  - 互斥：解决同一时刻不能同时使用同一临界资源的问题。  
  - 同步：解决操作先后顺序的配合问题。
- `x += 1` 这类语句通常不是原子操作，考试中默认要按“读-改-写”来分析并发风险。
