## 答案

**C. 信号量方法。**  
理由是：只有信号量机制能在进程暂时无法进入临界区时，使其进入阻塞态并释放处理机，从而满足“让权等待”。

## 解析

题干考查的是进程互斥中的“让权等待”原则。其含义是：当进程暂时不能进入临界区时，应立即释放处理机，而不是占着 CPU 反复检查条件。

判断本题的关键，在于区分两类等待方式：

- **忙等 / 自旋等待**：进程进不了临界区时，仍持续占用 CPU 检查条件，不能实现让权等待。
- **阻塞等待**：进程进不了临界区时，主动放弃处理机，进入阻塞态，能够实现让权等待。

在四个选项中：

- `Peterson` 方法属于软件互斥算法，等待时本质上仍是循环检查条件，属于忙等。
- `swap` 指令和 `TestAndSet` 指令属于硬件实现互斥的方式，通常构成自旋锁，等待时也不释放处理机，仍是忙等。
- **信号量方法**中，进程执行 `P` 操作后，若资源不足，则会被阻塞，不再继续占用 CPU；等资源可用时再被唤醒。因此它满足让权等待。

所以正确答案是 **C**。

## 选项分析

**A. Peterson 方法：错误。**  
`Peterson` 方法可以实现互斥，也能保证一定的有限等待，但当进程无法进入临界区时，需要持续循环判断条件，属于忙等，不满足让权等待。

**B. swap 指令：错误。**  
`swap` 是硬件原子指令，常用于实现互斥锁。其典型实现方式是自旋等待，进程拿不到锁时不会立即释放处理机，因此不满足让权等待。

**C. 信号量方法：正确。**  
信号量，尤其是带阻塞队列的记录型信号量，在执行 `P` 操作且资源不足时，会使进程进入阻塞态。阻塞意味着释放处理机，因此能够实现让权等待。

**D. TestAndSet 指令：错误。**  
`TestAndSet` 与 `swap` 类似，也是硬件原子指令，常用于实现自旋锁。等待期间持续占用 CPU，不满足让权等待。

## 易错点

- 容易把“**有限等待**”和“**让权等待**”混淆。  
  `Peterson` 方法能保证有限等待，但这不等于能让权等待；它等待时仍然是忙等。

- 容易误以为“能实现互斥”就一定“满足互斥原则的全部要求”。  
  实际上，`Peterson`、`swap`、`TestAndSet` 都能实现互斥，但都存在忙等问题，不能实现让权等待。

- 本题中的“信号量方法”应理解为带阻塞/唤醒机制的实现。若只是单纯自旋检查的伪实现，则不满足题意；但按教材与标准答案，应判为 **C**。
