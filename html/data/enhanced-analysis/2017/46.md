## 答案

应按共享变量上的实际冲突关系设置 3 个互斥信号量，并在相应语句前后加入 `P`、`V` 操作，以保证互斥且尽量提高并发性。

可行写法为：

- `semaphore y_mutex1 = 1;`
- `semaphore y_mutex2 = 1;`
- `semaphore z_mutex = 1;`

其中：

- `y_mutex1`：用于 `thread1` 与 `thread3` 在 `y` 上的读写互斥
- `y_mutex2`：用于 `thread2` 与 `thread3` 在 `y` 上的读写互斥
- `z_mutex`：用于 `thread2` 与 `thread3` 在 `z` 上的读写互斥

伪代码可写为：

```c
semaphore y_mutex1 = 1;
semaphore y_mutex2 = 1;
semaphore z_mutex = 1;

// 全局变量 x, y, z
cnum x, y, z;

thread1()
{
    cnum w;
    P(y_mutex1);
    w = add(x, y);
    V(y_mutex1);
    // ...
}

thread2()
{
    cnum w;
    P(z_mutex);
    P(y_mutex2);
    w = add(y, z);
    V(y_mutex2);
    V(z_mutex);
    // ...
}

thread3()
{
    cnum w;
    w.a = 1;
    w.b = 1;

    P(z_mutex);
    z = add(z, w);
    V(z_mutex);

    P(y_mutex1);
    P(y_mutex2);
    y = add(y, w);
    V(y_mutex2);
    V(y_mutex1);
    // ...
}
```

## 解析

### 冲突关系分析

本题的关键是先判断 3 个线程在各共享变量上的访问类型，再决定哪些位置需要互斥。

判定原则是：

- 读-读可以并发，不必互斥；
- 读-写必须互斥；
- 写-写必须互斥。

由题意可知：

- `thread1`：读 `x`、读 `y`
- `thread2`：读 `y`、读 `z`
- `thread3`：更新 `z`、更新 `y`

其中，`z = add(z, w)` 和 `y = add(y, w)` 虽然右侧先读取旧值，但整体效果是改写共享变量，因此都应按“写”处理。

据此逐个分析：

1. 对 `x`：
   只有 `thread1` 访问，其他线程不访问，因此不构成冲突，不需要加锁。

2. 对 `y`：
   - `thread1` 读 `y`
   - `thread2` 读 `y`
   - `thread3` 写 `y`

   所以：
   - `thread1` 与 `thread2` 是读-读关系，可并发；
   - `thread1` 与 `thread3` 是读-写关系，必须互斥；
   - `thread2` 与 `thread3` 是读-写关系，必须互斥。

   因而需要用两个互斥信号量分别协调这两组冲突：`y_mutex1` 和 `y_mutex2`。

3. 对 `z`：
   - `thread2` 读 `z`
   - `thread3` 写 `z`

   这是读-写冲突，需要用 `z_mutex` 实现互斥。

### 信号量设置与加锁位置

题目要求“确保线程互斥访问临界资源，并且最大程度地并发执行”，因此不能把所有共享变量统一放到一个总互斥区中，否则会把本来可以并发的访问也串行化。

本题应只对真正发生冲突的访问加锁：

- `thread1` 只需在访问 `y` 时使用 `y_mutex1`，访问 `x` 不必加锁；
- `thread2` 访问 `y`、`z` 时分别受 `y_mutex2`、`z_mutex` 约束；
- `thread3` 更新 `z` 时要与 `thread2` 互斥，因此使用 `z_mutex`；
- `thread3` 更新 `y` 时同时与 `thread1`、`thread2` 冲突，因此要同时申请 `y_mutex1` 和 `y_mutex2`。

这样处理后：

- `thread1` 与 `thread2` 对 `y` 的读取仍可并发；
- 与 `x` 无关的操作不会被无故阻塞；
- 只有真正存在读写冲突的位置才互斥，符合“最大程度地并发执行”的要求。

## 易错点

- 不能只设置 1 个总互斥信号量。这样虽然能保证正确性，但会降低并发度，不符合题意。
- `thread3` 中的 `y = add(y, w)`、`z = add(z, w)` 应按“写共享变量”处理，必须与其他线程对同一变量的读操作互斥。
- `thread1` 与 `thread2` 虽然都访问 `y`，但二者都是读操作，不冲突，不应额外串行化。
- `thread3` 写 `y` 时同时涉及两组冲突，因此必须同时受 `y_mutex1` 和 `y_mutex2` 约束。
