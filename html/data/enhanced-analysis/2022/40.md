## 答案
选 `B`，所需时间至少为 $40\text{ ms}$。

## 解析
题目考察 `HTTP/1.1` 下的网页获取过程，并且已知：

- `HTTP/1.1` 默认使用持续连接和流水线
- `news408.html` 大小为 $1\text{ MSS}$
- 图像大小为 $3\text{ MSS}$
- $RTT = 10\text{ ms}$
- 忽略 HTTP 响应首部开销和 TCP 段传输时延
- 已完成域名解析

要求的是从“开始建立 TCP 连接”到“收到全部内容”的最短时间，因此应按理想情况分析：

- TCP 三次握手时，在第三个报文段中捎带 `HTTP` 请求
- 不考虑拥塞和流量控制，发送窗口可按慢开始中的拥塞窗口变化
- 初始 $cwnd = 1\text{ MSS}$

传输过程如下：

- 第 1 个 `RTT`：完成 TCP 连接建立，并在第三次握手中发送对 `news408.html` 的请求。
- 第 2 个 `RTT`：服务器返回大小为 $1\text{ MSS}$ 的 `HTML` 文件。此后慢开始使 `cwnd` 增至 $2\text{ MSS}$。
- 第 3 个 `RTT`：服务器发送图像文件前 $2\text{ MSS}$ 的数据。主机确认后，`cwnd` 增至 $4\text{ MSS}$。
- 第 4 个 `RTT`：服务器发送剩余 $1\text{ MSS}$ 的图像数据，传输完成。

因此总时间为

$$4 \times 10\text{ ms} = 40\text{ ms}$$

## 选项分析
- `A. 30ms`：少算了一个 `RTT`，不符合握手加两轮数据传输再补发剩余数据的过程。
- `B. 40ms`：正确。
- `C. 50ms`：对应 $5\text{ RTT}$，本题不需要。
- `D. 60ms`：对应 $6\text{ RTT}$，明显偏大。

## 易错点
- `HTTP/1.1` 默认是持续连接，但这题的关键不是复用多个对象请求，而是 `TCP` 连接建立后按慢开始发送数据。
- 图像大小是 $3\text{ MSS}$，而初始 `cwnd` 只有 $1\text{ MSS}$，不能一次发完。
- 题目问“至少时间”，要按最理想情况算，第三次握手可捎带 `HTTP` 请求。
