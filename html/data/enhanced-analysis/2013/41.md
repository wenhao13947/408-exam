## 答案

(1) 基本设计思想：

采用“两遍扫描”：

第一遍从前到后扫描数组，用“抵消”的思路选出一个候选元素 `candidate`。  
若当前元素与候选相同，则计数加 1；否则计数减 1。当计数减为 0 时，改用当前位置元素作为新的候选，并将计数置为 1。这样扫描结束后，若主元素存在，则这个候选一定可能是主元素。

第二遍重新统计该候选元素在数组中的实际出现次数。  
若其出现次数大于 `n/2`，则它就是主元素；否则数组中不存在主元素，输出 `-1`。

(2) 算法实现如下。

(3) 时间复杂度为 `O(n)`，空间复杂度为 `O(1)`。

## 解析

### 解法一：暴力法

依次把每个元素当作候选值，再完整扫描数组统计它的出现次数；某个值出现次数大于 $n/2$ 时返回该值，否则最终返回 `-1`。时间复杂度为 $O(n^2)$，空间复杂度为 $O(1)$。

### 解法二：优化解法

使用候选抵消法先筛出唯一可能的主元素，再扫描一次确认次数，时间复杂度为 $O(n)$，空间复杂度为 $O(1)$。

> **考场建议：** 先写“逐个候选并计数”能保证思路正确，再从重复计数的瓶颈想到候选抵消；优化后仍必须做第二趟验证。

### (1) 基本设计思想

题目要求找出出现次数严格大于 `n/2` 的元素。这里最有效的方法是先“筛候选”，再“做确认”。

核心依据是：

- 若一个元素是主元素，它的出现次数比其余所有元素出现次数之和还多。
- 因此在顺序扫描时，可以把“一个候选元素”和“一个与它不同的元素”两两抵消。
- 抵消完成后，如果主元素存在，它不可能被全部抵消掉，最终留下来的候选就只能是它。

具体分两步：

1. 选候选元素  
   设 `candidate` 表示当前候选，`count` 表示当前候选的有效计数。
   - 初始时可令第一个元素为候选，计数为 1；
   - 继续扫描后续元素：
     - 若当前元素等于候选，`count++`
     - 若当前元素不等于候选，`count--`
     - 若 `count` 变为 0，则说明当前这部分元素已两两抵消完毕，应将当前元素作为新的候选，并令 `count=1`

2. 验证候选是否真的是主元素  
   第一遍得到的只是“可能的主元素”，不一定真的超过半数，所以必须再扫描一遍，统计其真实出现次数。
   - 若次数 `> n/2`，返回该元素
   - 否则返回 `-1`

主元素的判定条件是出现次数大于 `n/2`。该算法对长度为 `n` 的数组做两次线性扫描，因此时间复杂度为 `O(n)`。

### (2) C 语言描述算法

```c
int majority(int a[], int n) {
    if (n == 0) {
        return -1;
    }

    // 第一遍：选出候选主元素
    int candidate = a[0];
    int count = 1;

    for (int i = 1; i < n; i++) {
        if (a[i] == candidate) {
            count++;
        } else {
            count--;
            if (count == 0) {
                candidate = a[i];
                count = 1;
            }
        }
    }

    // 第二遍：验证候选是否真为主元素
    int occur = 0;
    for (int i = 0; i < n; i++) {
        if (a[i] == candidate) {
            occur++;
        }
    }

    if (occur > n / 2) {
        return candidate;
    } else {
        return -1;
    }
}
```

### (3) 正确性说明

第一遍扫描中，算法做的是“不同元素两两抵消”。

设主元素为 `x`，它出现了 `m` 次，且 `m > n/2`。  
那么非 `x` 元素一共只有 `n-m` 个，并且有：

$$
m > n-m
$$

这说明即使把每个非 `x` 元素都拿去和一个 `x` 抵消，最终仍至少会剩下一个 `x`。  
因此，若主元素存在，第一遍扫描结束后保留下来的候选元素一定可能是 `x`。

但“可能是”还不够，因为在不存在主元素时，第一遍也会留下某个候选值。  
例如序列 `(1,2,3)` 扫描结束后也可能得到某个候选，但它并未超过半数。  
所以必须进行第二遍统计确认，只有当其出现次数满足：

$$
\text{occur} > \frac{n}{2}
$$

时，才能认定它是主元素；否则应输出 `-1`。

### (4) 复杂度分析

- 第一遍筛选候选：扫描一次数组，时间为 `O(n)`
- 第二遍统计次数：再扫描一次数组，时间为 `O(n)`

总时间复杂度为：

$$
O(n) + O(n) = O(n)
$$

算法中只使用了 `candidate`、`count`、`occur` 等常数个辅助变量，所以空间复杂度为：

$$
O(1)
$$

这与题目要求的“尽可能高效”是一致的。
