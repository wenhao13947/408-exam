## 答案

**D（仅Ⅰ、Ⅲ、Ⅳ）**。  
判断关键在于：**阻塞态表示进程因等待 CPU 以外的某种资源或事件而暂时无法继续执行**；如果只是暂时得不到 CPU，则应转入就绪态，而不是阻塞态。

## 解析

进程的三种相关状态可这样区分：

- **执行态**：正在占用 CPU 运行。
- **就绪态**：除 CPU 外，运行所需条件都已具备，只等 CPU。
- **阻塞态**：正在等待某个事件发生，或等待某类 **非 CPU 资源**，暂时不能运行。

据此分析本题：

- **读文件** 本质上通常对应 I/O 请求。若进程发出读文件操作后数据尚未就绪，就需要等待文件/磁盘 I/O 完成，因此可能由执行态转为阻塞态。
- **时间片用完** 时，说明进程当前并不是在等待其他资源，而只是 CPU 使用权被剥夺。此时进程仍具备运行条件，只是暂时没有 CPU，所以应从执行态转为**就绪态**。
- **申请外设** 时，如果外设不能立即满足，进程需要等待外设资源，属于等待 CPU 以外的资源，因此可能进入阻塞态。
- **执行信号量的 `wait()` 操作** 时，若对应资源暂不可用，进程需要等待该信号量满足条件后再继续执行，因此可能进入阻塞态。

因此，可能导致进程由执行态变为阻塞态的是 **Ⅰ、Ⅲ、Ⅳ**，答案为 **D**。

## 选项分析

A. **仅Ⅰ、Ⅳ**  
错误。漏掉了 **Ⅲ**。申请外设在不能立即分配时，进程也可能阻塞。

B. **仅Ⅱ、Ⅲ**  
错误。  
- **Ⅱ** 错在把“时间片用完”误判为阻塞。时间片用完后进程进入的是**就绪态**。  
- 同时漏掉了 **Ⅰ** 和 **Ⅳ**。

C. **仅Ⅲ、Ⅳ**  
错误。漏掉了 **Ⅰ**。读文件通常属于 I/O 等待，也可能使进程阻塞。

D. **仅Ⅰ、Ⅲ、Ⅳ**  
正确。三者都可能让进程等待 CPU 以外的资源或事件，从而进入阻塞态；只有 **Ⅱ** 是等待 CPU，应转入就绪态。

## 易错点

- 不要把**“拿不到 CPU”**和**“阻塞”**混为一谈。  
  - 等 CPU：**就绪态**  
  - 等 I/O、外设、信号量等：**阻塞态**
- 题干问的是 **“可能导致”**。因此不要求某操作必然阻塞，只要在常见条件下可能引发等待即可。
- 对 `wait()` 的判断要注意语义：并非执行 `wait()` 一定阻塞，而是在资源条件不满足时会阻塞。本题问“可能”，所以 **Ⅳ** 应选。
