## 答案

**D. 被高优先级进程抢占。**  
因为被抢占时，进程失去的只是处理机（CPU）资源，其他运行所需资源仍已具备，因此状态由**执行态**转为**就绪态**，而不是阻塞态。

## 解析

本题考查进程三种基本状态及其转换条件。判断关键不在于“发生了什么动作”，而在于该动作发生后，进程**到底缺不缺除 CPU 之外的其他资源**。

三种状态可概括为：

- **执行态（运行态）**：已经占有 CPU，且其他所需资源也已具备，可以继续执行。
- **就绪态**：除 CPU 外，其他资源都已具备，只是在等待处理机分配。
- **阻塞态**：不仅没有 CPU，而且还在等待某个事件发生或某种资源到位，因此暂时不能继续执行。

因此，从**执行态变为就绪态**的本质是：

- 进程只是**暂时失去 CPU**
- 但**并不缺少其他资源**

而从**执行态变为阻塞态**的本质是：

- 进程在执行过程中**申请了某种尚未满足的资源**，或需要等待某个事件完成
- 此时即使给它 CPU，它也无法继续运行，所以会进入阻塞态

题干问的是“会导致进程从执行态变为就绪态的事件”，所以应选那种**仅剥夺处理机、不引入资源等待**的情况。

## 选项分析

**A. 执行 P(wait) 操作**  
错误。`P(wait)` 操作本质上是对某类资源的申请。若该资源当前不可用，进程就需要等待该资源，说明它已经不只是缺少 CPU，而是缺少某种其他资源，因此应由执行态转为**阻塞态**。

**B. 申请内存失败**  
错误。内存属于系统资源。申请失败说明该进程暂时得不到所需内存，必须等待资源满足后才能继续执行，所以会由执行态转为**阻塞态**，不是就绪态。

**C. 启动 I/O 设备**  
错误。启动 I/O 后，进程通常需要等待 I/O 相关操作完成或设备就绪。在等待期间，进程无法继续执行，属于等待外设事件或资源满足，因此应转为**阻塞态**。

**D. 被高优先级进程抢占**  
正确。高优先级进程抢占的是 **CPU 使用权**。原进程并没有缺失内存、I/O 设备或其他运行资源，只是暂时得不到处理机，因此由执行态转为**就绪态**。一旦再次获得 CPU，就可以继续运行。

## 易错点

- **就绪态不是“什么都没有”**，而是“**除了 CPU，其他都已经有了**”。
- **阻塞态也没有 CPU**，但它与就绪态的区别在于：阻塞态还在**等待其他资源或事件**。
- 做这类题时，可直接用一句话判定：  
  **若只失去 CPU，则到就绪态；若还要等待资源或事件，则到阻塞态。**
