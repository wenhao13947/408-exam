## 答案

D. 减少指令流水线资源冲突

## 解析

采用指令 Cache 与数据 Cache 分离，主要目的是**减少指令流水线中的资源冲突**，也就是减少结构冒险。

原因在于：流水线运行时，处理器可能一边要**取指令**，另一边又要**访问数据**。如果指令和数据共用同一 Cache 或同一访存通路，这两类访问就可能在同一时刻争用同一存储资源，导致流水线等待。将指令 Cache 与数据 Cache 分离后，取指和数据访问分别使用不同的 Cache，资源争用显著减少，因此更有利于流水线并行工作。

本题问的是“**主要目的是**”。这里的考点不是一般性的 Cache 性能优化，而是流水线中的结构设计问题。指令 Cache 与数据 Cache 分离，首先解决的是**取指与数据访存的竞争**，所以应选 D。

还要注意一个概念边界：这里所说的冲突，指的是流水线中的**结构冒险**，不是寄存器读操作造成的冲突。普通指令在译码阶段读取操作数，读的是寄存器；而本题讨论的是取指与数据访存对同一存储资源的争用，这两者不能混淆。

## 选项分析

**A. 降低 Cache 的缺失损失**

错误。  
Cache 缺失损失是发生缺失后，为取回所需块而额外付出的时间代价。指令 Cache 与数据 Cache 分离的直接目的不是降低缺失损失，而是把取指和数据访问分开，减少它们对同一资源的争用，因此 A 不符合题意。

**B. 提高 Cache 的命中率**

错误。  
分离指令 Cache 和数据 Cache，在某些具体实现中可能对命中情况产生一定影响，但这不是该结构设计的主要目的。本题考查的是流水线中的资源冲突问题，因此 B 不是正确答案。

**C. 降低 CPU 平均访存时间**

错误。  
平均访存时间是一个综合性能指标，受命中率、缺失代价、层次结构设计等多种因素影响。指令 Cache 与数据 Cache 分离的核心出发点不是直接优化这一指标，而是减少流水线中取指与数据访存的冲突，所以 C 过于宽泛，不是本题所求。

**D. 减少指令流水线资源冲突**

正确。  
指令 Cache 与数据 Cache 分离后，取指和数据访问使用不同的存储部件，可减少对同一资源的竞争，从而减少流水线中的结构冒险。这正是题目所问的主要目的。

## 易错点

1. 把本题误做成“Cache 性能指标”题。  
题目问的是“主要目的是”，重点在体系结构中的流水线资源分配，而不是命中率、缺失损失等一般指标。

2. 把“取数”一概理解为访存。  
普通指令译码时读取的是寄存器内容，不属于这里讨论的存储器资源冲突。本题中的关键冲突，是**取指**和**数据访存**可能同时争用同一存储资源。

3. 误选 C。  
“降低 CPU 平均访存时间”听起来像性能提升，但它不是本题要考查的直接、主要目的；D 的表述更准确，也更符合题干。
