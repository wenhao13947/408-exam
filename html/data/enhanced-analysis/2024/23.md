## 答案
A。中断或异常发生时，CPU 的当前态不一定固定为内核态，可能是用户态，也可能已在内核态中处理其他事件。

## 解析
本题考查中断、异常、系统调用和中断处理程序的基本概念。

A 项错误。中断或异常“发生时”CPU 所处状态不能一概而论。  
- 如果是在执行用户程序指令过程中触发，CPU 可能处于用户态。  
- 如果是在内核态执行过程中再次发生中断或异常，例如多重中断场景，CPU 也可能处于内核态。  
因此，不能笼统说“中断或异常发生时 CPU 处于内核态”。

B 项正确。系统调用是操作系统向用户提供的申请操作系统服务的接口，每种系统调用都有对应的内核服务例程负责处理。

C 项正确。中断处理程序属于操作系统提供的服务，通常位于内核空间，开始执行时 CPU 必须处于内核态，才能访问相应地址空间并执行特权操作。

D 项正确。系统增加新类型设备时，设备驱动通常需要注册相应的中断服务例程，以便设备产生中断时能够被正确处理。

## 选项分析
A. 错误。中断/异常发生时 CPU 状态不确定，不能直接断言一定是内核态。  
B. 正确。系统调用对应内核中的服务例程。  
C. 正确。中断处理程序在内核态执行。  
D. 正确。新设备接入后通常需要注册对应中断服务例程。

## 易错点
- “发生时”和“开始处理时”不是一回事。题目考的是事件触发瞬间，CPU 状态可能是用户态，也可能是内核态。
- 中断、异常、系统调用都可能引发从用户态到内核态的切换，但触发时 CPU 所处状态不能统一概括。
