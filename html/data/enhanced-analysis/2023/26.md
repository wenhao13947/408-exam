## 答案
D。系统调用执行完毕后，CPU 会从内核态返回用户态。

## 解析
题干问的是“哪种操作完成时，会导致 CPU 从内核态转为用户态”。关键点不在于“谁来执行”，而在于“操作结束后 CPU 模式是否回到用户态”。

系统调用的过程是：用户程序先通过系统调用接口请求操作系统服务，随后借助 `INT`、`trap` 等方式进入内核态执行内核代码；当内核服务处理完成后，再通过设置 `CPU PSW` 中的 CPU 模式位，使 CPU 返回用户态继续执行用户程序。因此，系统调用完成时，确实会发生从内核态到用户态的切换。

A、B、C 这三项都属于操作系统在内核态下进行的进程管理或调度行为，但它们完成后是否立刻回到用户态并不固定，不能据此确定一定发生内核态到用户态的切换。

## 选项分析
A. 阻塞过程：阻塞进程时，操作系统会修改进程状态、把进程放入阻塞队列，但操作结束后不一定立刻切回用户态。  
B. 执行 CPU 调度：调度发生在内核态，且下一个运行的对象可能是用户进程，也可能是内核进程，不能据此确定 CPU 一定转回用户态。  
C. 唤醒进程：唤醒只是把进程从阻塞队列移到就绪队列，后续是否马上运行以及 CPU 是否回到用户态都不确定。  
D. 执行系统调用：先进入内核态执行服务，完成后再返回用户态，符合题意。

## 易错点
这题容易把“由操作系统完成”误当成“CPU 一定回到用户态”。实际上，决定模式切换的是操作完成后的返回路径；四个选项里只有系统调用的完整流程明确包含“内核态执行后返回用户态”。
