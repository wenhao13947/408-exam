## 答案

选 **C. f, d, e**。

## 解析

本题要求按 Dijkstra 算法确定从源点 `a` 到其余顶点的最短路径被“依次确定”的顺序。题干已经明确给出前两次确定的顶点分别是 `b`、`c`，因此只需继续比较后续各未确定顶点的当前最短距离。

结合题图及可核验的路径长度关系，可得：

- 到 `b` 的最短距离：`a -> b = 2`
- 到 `c` 的最短距离：`a -> b -> c = 3`，优于 `a -> c = 5`

这与题干“第一条是 `b`，第二条是 `c`”一致。接下来继续向后推。

从图上顺着边方向看，在确定了 `b`、`c` 之后，当前可得到：

| 顶点 | 当前最短路径 | 当前最短距离 |
|---|---|---:|
| `f` | `a -> b -> c -> f` | 4 |
| `d` | `a -> b -> d` | 5 |
| `e` | `a -> b -> c -> e` | 7 |

因此第三次应先选当前距离最小的 `f`。

然后考察把 `f` 加入集合 `S` 后是否会改写别的顶点距离。由图可知，`f` 不会把 `d` 或 `e` 更新得更短，所以此时仍有：

- `d = 5`
- `e = 7`

故第四次确定的是 `d`。

再由 `d` 对外松弛，可把 `e` 更新为：

$$
a \to b \to d \to e = 2 + 3 + 1 = 6
$$

它优于原先经 `c` 得到的 `7`，所以最后确定的是 `e`。

综上，后续顺序为：

$$
f,\ d,\ e
$$

对应选项 **C**。

按距离逐步更新集合 `S` 后，正确顺序仍是 `f, d, e`。

## 选项分析

**A. `d, e, f`**

错误。确定完 `c` 后，已有：

- `a -> b -> c -> f = 4`
- `a -> b -> d = 5`

因为 `4 < 5`，第三个确定的应当是 `f`，不可能先是 `d`。

**B. `e, d, f`**

错误。确定完 `c` 后，`e` 的当前最短距离是 `7`，而此时：

- `f = 4`
- `d = 5`

所以 `e` 不可能排在 `f`、`d` 前面。

**C. `f, d, e`**

正确。确定完 `c` 后先有 `f = 4`、`d = 5`、`e = 7`，故先选 `f`；`f` 不再带来更短更新，所以下一个是 `d`；再由 `d` 把 `e` 更新为 `6`，最后选 `e`。

**D. `f, e, d`**

错误。第三个选 `f` 是对的，但在 `f` 加入后，当前仍是：

- `d = 5`
- `e = 7`

所以第四个应当先选 `d`，而不是 `e`。

## 易错点

1. 容易把“图上离得近”误当成“最短路径先确定”。  
   Dijkstra 比较的是当前从源点出发的路径总权值，不是图形位置。

2. 容易忽略“当前最短距离”会被后续松弛更新。  
   例如 `e` 在确定 `c` 后先得到的是 `7`，但在确定 `d` 后还能更新为 `6`。

3. 应按当前最短距离逐步判断路径。  
   `e`、`f` 的判断顺序应以可复核的距离比较为准。
