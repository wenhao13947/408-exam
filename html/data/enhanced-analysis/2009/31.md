## 答案

**B．`1、1`**

理由：`F2` 是 `F1` 的符号链接（软链接），本质上是一个保存目标路径名的独立文件，不参与 `F1` 所在 inode 的链接计数；`F3` 是 `F1` 的硬链接，与 `F1` 指向同一个 inode。建立 `F3` 后该 inode 引用计数加 1，删除 `F1` 后再减 1，最终 `F3` 对应的引用计数为 `1`，而 `F2` 自身仍为 `1`。

## 解析

题干给出：文件 `F1` 的当前引用计数值为 `1`。

这表示初始时只有一个目录项（`F1`）链接到该文件的 inode，因此：

- `F1` 对应 inode 的链接计数为 `1`

接下来按操作顺序分析。

### 第一步：建立 `F1` 的符号链接 `F2`

符号链接（软链接）的本质是一个**独立文件**，其内容通常是目标文件的路径名。  
因此，建立 `F2` 后：

- `F2` 作为一个新文件被创建，它自身可视为引用计数为 `1`
- `F1` 对应 inode 的链接计数**不变**，仍为 `1`

也就是说，软链接不会给目标文件的 inode 增加一个新的目录项引用。

### 第二步：建立 `F1` 的硬链接 `F3`

硬链接的本质是：再创建一个新的目录项 `F3`，让它与 `F1` **指向同一个 inode**。

因此，建立 `F3` 后：

- `F1` 和 `F3` 共同指向同一个 inode
- 该 inode 的链接计数从 `1` 增加到 `2`

此时可以理解为：

- `F1` 和 `F3` 是同一个文件的两个名字
- 共享同一份文件数据、同一个 inode

### 第三步：删除 `F1`

删除普通文件名，本质上是删除一个目录项。  
因此删除 `F1` 后：

- `F1` 这个名字消失
- 原 inode 仍被 `F3` 引用，所以不会立即删除
- 该 inode 的链接计数从 `2` 减少到 `1`

而 `F2` 是软链接，它只是保存了原目标路径。删除 `F1` 并不会让 `F2` 的“自身文件”消失，因此其自身仍是一个存在的文件，计数保持 `1`。只是它所指向的原路径目标已不存在，成为悬空链接（dangling link）。

所以最终：

- `F2 = 1`
- `F3 = 1`

## 选项分析

A．`0、1`  
错误。删除 `F1` 不会直接删除符号链接 `F2` 本身，`F2` 仍然是一个独立存在的链接文件，不会变成 `0`。

B．`1、1`  
正确。`F2` 作为软链接自身仍存在，计数为 `1`；`F3` 与 `F1` 共享 inode，建立时计数加 `1`，删除 `F1` 时再减 `1`，最终为 `1`。

C．`1、2`  
错误。若 `F3 = 2`，说明删除 `F1` 后 inode 的链接计数没有减少，这不符合删除目录项的规则。删除 `F1` 后应由 `2` 变为 `1`。

D．`2、1`  
错误。软链接不会因为目标文件存在或硬链接数量变化而使自身计数变为 `2`。`F2` 是独立文件，不与 `F1`/`F3` 共享 inode。

## 易错点

- **不要把软链接当成硬链接。**  
  软链接不增加目标文件 inode 的链接计数；硬链接才会增加。

- **删除的是文件名，不一定是文件数据。**  
  删除 `F1` 后，只是少了一个目录项；只要还有 `F3` 指向同一 inode，该文件就仍然存在。

- **区分“软链接自身存在”与“软链接目标是否存在”。**  
  删除 `F1` 后，`F2` 可能失效，但 `F2` 这个链接文件本身并未被删除。
