## 答案

C。因为线程从执行态变为就绪态的前提是：线程暂时失去 CPU，但运行所需的其他资源仍然都已具备；四个选项中只有“主动出让 CPU”符合这一条件。

## 解析

本题考查线程状态转换的基本判断。

执行态表示线程正在占用 CPU 运行，同时它所需的其他资源也已经具备。就绪态表示线程已经具备运行条件，只是当前没有获得 CPU。可以概括为：

- 执行态：有 CPU，且其他运行条件齐备
- 就绪态：无 CPU，但其他运行条件齐备

因此，若线程要从执行态变为就绪态，关键特征是“只失去 CPU，不额外等待其他资源”。

据此分析各选项：

- 如果线程因为某种原因需要等待 I/O 完成，说明它不只是缺 CPU，而是在等待外部资源，这种情况应转入阻塞态，而不是就绪态。
- 如果线程执行同步原语后因资源不足而不能继续执行，也是在等待某种条件满足，仍应进入阻塞态。
- 只有线程主动让出 CPU 时，它本身并没有缺少除 CPU 之外的任何资源，因此会由执行态回到就绪态，等待再次调度。

所以正确答案为 C。

## 选项分析

A. 键盘输入

错误。键盘输入属于 I/O 相关事件。当前线程若发起并等待键盘输入结果，本质上是在等待 I/O 完成，因此会由执行态转为阻塞态，而不是就绪态。

B. 缺页异常

错误。发生缺页异常后，若所需页面不在内存，操作系统通常需要将页面从外存调入内存。这个过程往往伴随 I/O 等待，因此线程会从执行态转为阻塞态。它不是“只缺 CPU”，所以不转为就绪态。

C. 主动出让 CPU

正确。主动出让 CPU 仅表示当前线程放弃处理机使用权，但线程继续运行所需的其他资源仍然满足，因此状态从执行态变为就绪态，等待后续再次被调度。

D. 执行信号量的 `wait()` 操作

错误。信号量的 `wait()` 对应经典的 `P` 操作。当信号量值不足、资源不可用时，线程无法继续执行，会被阻塞，等待资源可用后再唤醒。因此这类情况是执行态到阻塞态，而不是执行态到就绪态。

## 易错点

- 不要把“失去 CPU”一律看成进入就绪态。只有在线程不需要等待任何其他资源时，才是执行态到就绪态。
- 只要题目中的事件涉及 I/O 等待、页面调入、同步资源不足等，都更应优先判断为进入阻塞态。
- `wait()` 并不必然阻塞，但题干问的是“可能导致”哪种状态变化；`wait()` 在资源不足时确实可能使线程进入阻塞态，因此不能选。
