## 答案

**D**。因为缺页属于异常中的 **fault（故障）**，缺页处理完成后应返回到**发生缺页的那条指令重新执行**，而不是执行下一条指令。

## 解析

本题考查请求分页系统中的**缺页异常处理流程**。

在请求分页系统中，程序执行某条指令时，如果访问的页当前**不在内存**，那么在地址转换过程中，CPU 会检测到这一情况并产生缺页异常。随后由操作系统的缺页处理程序介入，将所需页面从外存调入内存，待页面装入后，再恢复进程执行。

判断本题的关键，不在于“是否会返回原进程”，而在于**返回后从哪条指令开始执行**。

缺页属于一种可以被修复的异常，即 **fault**。这类异常的特点是：处理完成后，CPU 需要回到**引发故障的那条指令**重新执行，因为原指令此前并未成功完成。只有重新执行该指令，才能在页面已经装入内存的前提下正确完成本次访存操作。

因此，题干中“缺页处理完成后回到发生缺页的指令的下一条指令执行”的说法错误。

## 选项分析

**A. 缺页是在地址转换时 CPU 检测到的一种异常**

正确。  
缺页发生在指令执行期间的地址转换阶段，当 CPU 发现所访问页面不在内存时，会触发缺页异常。它属于**内部异常**，不是外部中断。

**B. 缺页处理由操作系统提供的缺页处理程序来完成**

正确。  
缺页处理不是用户程序自行完成的，而是由操作系统内核中的缺页处理程序负责，包括查找页表信息、分配物理块、必要时进行页面置换、从外存调页等操作。

**C. 缺页处理程序根据页故障地址从外存读入所缺失的页**

正确。  
发生缺页后，系统可根据故障相关地址定位所需页面，并结合页表项中的外存信息，将相应页面从外存调入内存。该说法表述不算特别细，但基本判断是正确的。

**D. 缺页处理完成后回到发生缺页的指令的下一条指令执行**

错误。  
缺页属于 **fault**，处理完成后应返回到**引发缺页的那条指令**重新执行，而不是下一条指令。若直接执行下一条，原先那条因缺页未完成的指令就会被跳过，显然不符合程序执行语义。

## 易错点

- 容易把“异常处理结束后继续执行”误解为“从下一条指令开始执行”。对缺页这种 **fault** 来说，应该是**重启原指令**。
- 要区分**内部异常**与**外部中断**：缺页是执行指令时产生的内部异常，不是外设发来的中断。
- 选项 C 的说法容易让人纠结术语细节，但本题核心争议点不在 C，而在 D 对返回执行位置的判断。
