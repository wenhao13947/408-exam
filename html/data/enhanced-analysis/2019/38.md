## 答案

**C．$t_3$。**  
因为 TCP 支持快速重传时，发送方一旦收到对同一确认号的 **3 个重复 ACK**，就会立即重传丢失的报文段，不必等到重传计时器超时。

## 解析

题干给出的关键条件是：

- 在 $t_0$ 时刻，客户第一次收到 `ack_seq=100` 的确认段；
- 随后发送 `seq=100` 的数据段；
- 但该数据段丢失；
- TCP 支持 **快速重传（Fast Retransmit）**。

先解释 `ack_seq=100` 的含义：它表示接收方已经按序收到序号小于 100 的数据，**下一步期望收到的就是 `seq=100` 的报文段**。

现在 `seq=100` 丢失了。此后，发送方若又发送了后续序号的数据段，接收方即使收到了这些“后到”的报文段，也因为 `seq=100` 还没到，无法继续按序交付，于是会反复返回相同的确认，即重复发送 `ack_seq=100`。

TCP 的快速重传规则是：

- 当发送方连续收到 **3 个重复 ACK** 时，
- 就可判断某个较早的报文段很可能已经丢失，
- 于是**立即重传**该丢失段，
- 而**不等待**重传定时器超时。

根据题意和标准答案可知，到 $t_3$ 时刻，发送方已经收到了 3 个重复的 `ack_seq=100`，因此此时就会触发快速重传，重新发送 `seq=100`。

所以重新发送 `seq=100` 的时刻是 **$t_3$**。

## 选项分析

**A．$t_1$**  
错误。此时还不足以说明发送方已经收到了 3 个重复 ACK，不能触发快速重传。

**B．$t_2$**  
错误。与 $t_1$ 同理，若重复 ACK 数量未达到 3，发送方仍不会立即执行快速重传。

**C．$t_3$**  
正确。到该时刻已满足“收到 3 个重复 ACK”的触发条件，发送方立即重传 `seq=100`。

**D．$t_4$**  
错误。$t_4$ 对应的是等待重传计时器超时后再重传的思路；但题目已明确“TCP 支持快速重传”，因此无需等到 $t_4$。

## 易错点

- **快速重传不是等超时重传。**  
  只要收到 3 个重复 ACK，就可以提前重传。

- **“3 个重复 ACK”要理解准确。**  
  指的是对同一确认号的重复确认，例如连续收到多个 `ack_seq=100`。

- **不要把快速重传和重传定时器对立起来。**  
  快速重传并没有取消超时重传机制，只是在满足条件时更早触发。
