## 答案

### （1）
Web 服务器的 IP 地址是 `64.170.98.32`。  
该主机默认网关的 MAC 地址是 `00-21-27-21-51-ee`。

### （2）
主机使用 `ARP` 协议确定目的 MAC 地址。  
封装该 ARP 请求报文的以太网帧目的 MAC 地址是 `FF-FF-FF-FF-FF-FF`。

### （3）
需要 `6` 个 RTT。

### （4）
该 IP 分组经过路由器 `R` 转发时，需修改 IP 分组头中的字段是：`源 IP 地址`、`TTL`、`头部校验和`。  
其中源 IP 地址由 `10.2.128.100` 改为 `101.12.123.15`。

## 解析

### （1）
先由帧内容确定 Web 服务器的 IP 地址。

题 47-b 给出的帧前 14B 是以太网首部，结构如图可知依次为：

| 字段 | 长度 |
|---|---:|
| 目的 MAC | 6B |
| 源 MAC | 6B |
| 类型 | 2B |

因此 IP 数据报从第 `14` 字节开始。题图中类型字段为 `08 00`，说明其数据部分封装的是 IPv4 分组。

再看 IP 首部起始字节为 `45`：

- 高 4 位 `4` 表示 IPv4
- 低 4 位 `5` 表示 IP 首部长度为 $5 \times 4 = 20\text{B}$

IPv4 首部中，目的 IP 地址字段位于首部内第 `16~19` 字节，所以从整个以太网帧起始算，目的 IP 地址的起始偏移为：

$$14 + 16 = 30$$

结合题图逐字节读取，可得到这 4 个字节为：

$$40\ aa\ 62\ 20$$

将十六进制转成十进制：

- `40` -> `64`
- `aa` -> `170`
- `62` -> `98`
- `20` -> `32`

所以 Web 服务器 IP 地址为：

$$64.170.98.32$$

再求默认网关的 MAC 地址。题图最前面的 6B 就是该以太网帧的目的 MAC 地址：

$$00-21-27-21-51-ee$$

源主机 IP 是 `10.2.128.100`，目的服务器 IP 是 `64.170.98.32`，显然不在同一局域网，因此该帧在二层不会直接发给远端服务器，而是先发给默认网关 `10.2.128.1`。所以这个目的 MAC 地址就是默认网关接口的 MAC 地址。

另外要注意，题图每行前面的 `0000`、`0010`、`0020` 等只是显示偏移，不属于帧内容；读图时从真正的十六进制数据开始取字段即可。

### （2）
主机要发送该 Web 请求帧，必须先知道“下一跳”默认网关的 MAC 地址。已知的是默认网关的 IP 地址 `10.2.128.1`，要由 IP 地址解析出 MAC 地址，应使用 `ARP` 协议。

ARP 请求在以太网上采用广播发送，因此封装 ARP 请求报文的以太网帧目的 MAC 地址是全 1：

$$FF-FF-FF-FF-FF-FF$$

### （3）
题目已经明确两点：

1. `HTTP/1.1` 采用**持续连接**
2. 工作方式是**非流水线**

并且起点也说得很清楚：**“从发出题 47-b 图中的 Web 请求开始”**。  
这意味着这里不再计入 TCP 三次握手建立连接所需的 RTT，而是从这一次对 `rfc.html` 的 HTTP 请求已经发出时开始计时。

在持续连接、非流水线方式下：

- 同一个 TCP 连接可以复用
- 但必须收到前一个对象的响应后，才能发送下一个对象的请求

因此：

- 获取基础页面 `rfc.html`：`1` 个 RTT
- 页面中还引用了 `5` 个 JPEG 小图像，且非流水线下载，只能串行请求：再需要 `5` 个 RTT

总计：

$$1 + 5 = 6$$

所以共需要 `6` 个 RTT。

### （4）
该主机使用的是私有地址 `10.2.128.100`，而分组要发往 Internet。由拓扑图可知，路由器 `R` 的公网地址是 `101.12.123.15`，因此路由转发到公网时要进行 NAT，把 IP 分组头中的源地址改写为公网地址。

所以源 IP 地址要由：

$$10.2.128.100 \rightarrow 101.12.123.15$$

此外，IP 分组每经过一个路由器，`TTL` 都要减 `1`；而 IP 首部内容一旦变化，`头部校验和`就必须重新计算。

因此本题应答的必改字段是：

| 字段 | 修改情况 |
|---|---|
| 源 IP 地址 | 由 `10.2.128.100` 改为 `101.12.123.15` |
| TTL | 减 `1` |
| 头部校验和 | 重新计算 |

若分组长度超过输出链路 MTU，总长度、标志和片偏移也可能变化；这是一般性补充，不是本题的必答结论。本题按评分口径，应写出这里确定会修改的字段即可。

## 易错点

1. 第（1）问容易把远端 Web 服务器的 MAC 地址误当成帧目的 MAC。  
   实际上跨网段通信时，以太网帧的目的 MAC 是默认网关接口的 MAC，不是远端服务器的 MAC。

2. 第（1）问容易把题图每行前面的 `0000`、`0010` 等当成帧内容。  
   这些只是偏移标记，不参与字段解析。

3. 第（3）问容易多算 `1` 个 RTT。  
   本题起点是“从发出题 47-b 图中的 Web 请求开始”，因此不计 TCP 建连时间；若题目问“从开始访问该页面开始”，才需要把建连 RTT 计入。

4. 第（4）问不能把 IP 头所有字段都罗列一遍。  
   评分说明已经明确，这样作答不给分。应只写本题场景下转发必然修改的字段：`源 IP 地址`、`TTL`、`头部校验和`。

5. 第（1）问应按首部逐字节定位字段并复核。这里重新核算后，目的 IP 仍是 `64.170.98.32`，结论不变。
