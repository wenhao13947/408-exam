## 答案

**B**。  
多重中断系统中，CPU 并非在整个中断处理期间都处于关中断状态；通常只在保护现场和设置屏蔽字等关键阶段暂时关中断，进入正式中断服务后会重新开中断，以便受理更高优先级的中断。

## 解析

本题考查多重中断系统的基本工作机制，关键是区分“中断响应阶段”和“中断处理阶段”中 CPU 的中断开放状态。

多重中断的核心特征是：在处理某个中断的过程中，若出现更高优先级的中断请求，CPU 仍可继续响应。要做到这一点，CPU 不可能在整个中断处理期间一直关中断，否则就退化成不能嵌套的单重中断处理方式。

一般过程如下：

1. CPU 在当前指令执行结束后检查是否有中断请求。
2. 若有中断请求，则进入中断响应。
3. 在保护断点、保存现场、设置新的屏蔽字等操作时，通常暂时关中断，防止现场破坏。
4. 完成必要保护后，重新开中断，执行中断服务程序。
5. 这样在服务过程中，若有更高优先级中断到来，仍可再次打断当前处理过程。

因此，B 项把“中断处理期间”一概说成“CPU 处于关中断状态”，表述过于绝对，错误。

## 选项分析

**A. 在一条指令执行结束时响应中断**

正确。  
CPU 一般不会在一条指令执行到一半时去响应中断，而是在当前指令执行结束后、进入下一条指令之前检查并响应中断。这既适用于单重中断，也适用于多重中断。

**B. 中断处理期间 CPU 处于关中断状态**

错误。  
这是本题答案。多重中断系统为了允许更高优先级中断嵌套，在完成现场保护并设置好屏蔽字后，通常会重新开中断。因此不能笼统地说“中断处理期间 CPU 一直关中断”。

**C. 中断请求的产生与当前指令的执行无关**

正确。  
中断通常由外部设备或外部事件引起，其出现与当前正在执行的那条指令本身没有直接因果关系。与之相对，异常（Exception）通常由当前指令执行过程中产生，如除零、越界、非法操作码等，因此异常与当前指令执行有关。

**D. CPU 通过采样中断请求信号检测中断请求**

正确。  
CPU 识别中断请求的基本方式就是在规定时刻采样中断请求信号。常见表述是：在每条指令执行结束时采样中断请求线，若检测到有效请求，再决定是否进入中断响应周期。

## 易错点

**“关中断”不是全程状态**  
很多题目会把“保护现场时关中断”偷换成“整个中断处理过程都关中断”。对多重中断系统而言，这种说法是错的。判断时要抓住一句话：**若能实现中断嵌套，就说明处理中断时并非始终关中断。**

**区分中断与异常**  
- 中断：一般来自 CPU 外部事件，与当前指令执行无直接关系。  
- 异常：一般由当前指令执行引起，与当前指令直接相关。
