## 答案

**C（仅Ⅰ、Ⅱ）**。  
因为进程进入阻塞态的典型原因是：等待某种资源可用，或等待 I/O 完成；而被高优先级进程抢占 CPU 时，当前进程通常是由运行态转为就绪态，不是阻塞态。

## 解析

判断本题的关键，是区分“阻塞态”和“就绪态”的成因。

阻塞态表示进程虽然当前不能继续执行，但原因不是“没有 CPU”，而是它还在等待某个事件发生，例如等待资源、等待 I/O 完成。也就是说，进程是因为“等东西”而暂停执行。

就绪态表示进程已经具备运行条件，只是暂时没有获得 CPU。也就是说，它“不缺执行条件，只缺处理机”。

据此分析：

- 若进程 `P` 申请某个临界资源，而该资源正被其他进程占用，则 `P` 需要等待该资源释放，这属于等待资源，可能进入阻塞态。
- 若进程 `P` 从磁盘读数据，由于磁盘属于 I/O 设备，读操作完成前进程需要等待 I/O 结果，因此也可能进入阻塞态。
- 若系统把 CPU 分配给更高优先级的进程，这说明当前进程只是被剥夺了处理机使用权；只要它本身并未等待资源或 I/O，它仍具备运行条件，因此应由运行态转为就绪态，而不是阻塞态。

所以，可能导致当前进程 `P` 阻塞的事件只有 Ⅰ 和 Ⅱ，答案为 **C**。

## 选项分析

### Ⅰ. 进程 P 申请临界资源

**正确。**

临界资源在同一时刻只允许一个进程访问。若 `P` 申请时该资源已被占用，`P` 就必须等待资源释放。等待资源属于进入阻塞态的典型情形，因此该项可能导致阻塞。

### Ⅱ. 进程 P 从磁盘读数据

**正确。**

磁盘读操作属于 I/O 操作，进程发出读请求后，通常不能立即得到结果，需要等待 I/O 完成。在等待期间，进程会让出 CPU，自身进入阻塞态，因此该项也可能导致阻塞。

### Ⅲ. 系统将 CPU 分配给高优先级的进程

**错误。**

这是一种调度行为。若系统采用抢占式调度，当更高优先级进程进入就绪态时，当前运行进程可能被剥夺 CPU。但此时它并不是在等待资源或 I/O，而只是暂时得不到 CPU，所以状态变化应是：

$$运行态 
\rightarrow 就绪态$$

而不是：

$$运行态 
\rightarrow 阻塞态$$

因此该项不应选。

## 易错点

### 阻塞态与就绪态的区别

很多题目容易把“没法继续运行”都看成阻塞，这是错误的。应当这样区分：

- **阻塞态**：等待资源、等待 I/O、等待某事件发生。
- **就绪态**：除 CPU 外其他条件都满足，只是在等处理机。

### “被抢占”不等于“被阻塞”

高优先级进程抢占 CPU，是操作系统的调度结果，不代表当前进程在等待某个事件。因此被抢占后通常进入的是**就绪态**，不是**阻塞态**。
