## 答案

### （1）
应选择**链式存储结构**，具体可设计为**首尾相接的循环单链表队列**，设置两个指针 `front` 和 `rear`。

### （2）
初始状态：建立**仅含 1 个空闲结点**的循环单链表，且 `front` 和 `rear` 都指向该空闲结点。结合图可直接理解为：队列逻辑上为空，但物理上预留了 1 个可复用结点。

判空条件：`front == rear`

判满条件：`front == rear->next`

### （3）
第一个元素入队后，应为：原来的空闲结点中存放该元素，`rear` 移到其后的空闲结点。此时循环链表中共有 2 个结点，其中 1 个存放队列元素，1 个为空闲结点。结合图看，`front` 指向首元素所在结点，`rear` 指向下一空闲位置。

### （4）
入队操作基本过程：

1. 若 `front == rear->next`，则在 `rear` 之后插入一个新的空闲结点；
2. 将入队元素写入 `rear` 所指结点；
3. 令 `rear = rear->next`。

出队操作基本过程：

1. 若 `front == rear`，则队空，出队失败；
2. 取出 `front` 所指结点中的元素；
3. 令 `front = front->next`。

## 解析

### （1）
应选**链式存储结构**，不能选顺序存储结构。

题目要求同时满足：

1. 初始时队列为空；
2. 入队时允许增加队列占用空间；
3. 出队后，已占用空间可重复使用，且整个队列空间只增不减；
4. 入队、出队时间复杂度始终为 $O(1)$。

顺序存储的问题在于：若要“增加队列占用空间”，通常需要扩容；而顺序表扩容往往涉及重新申请更大连续空间并搬移原有元素，不能保证入队操作**始终**为 $O(1)$。因此它不符合题意。

链式存储更合适，原因有三点：

- 申请新结点方便，能满足“入队时允许增加空间”；
- 出队时不释放结点，只移动队头指针，被出队结点自然转为空闲结点，后续可复用，满足“空间只增不减”；
- 若维护 `front`、`rear` 两个指针，则入队和出队都只需常数次指针操作，时间复杂度可保持为 $O(1)$。

因此，本题应采用**循环链式队列**，即首尾相接的循环单链表实现。

### （2）
在第（1）问确定采用循环单链表后，初始状态就不能按普通链队列“一个结点也没有”去设计，而应按“保留一个空闲结点”的方式初始化。

初始时：

- 先建立 1 个空闲结点；
- 该结点的 `next` 指向自身，形成循环；
- `front`、`rear` 都指向该结点。

这样做的目的，是借用循环队列“牺牲一个单元区分队空与队满”的思想。

可用下表概括其判定规则：

**图解：初始循环单链表**

看清初始仅有一个空闲结点，且 front、rear 同指该结点。

![初始循环单链表](/data/enhanced-analysis/assets/2019/42/original-analysis-1.svg)

| 状态 | 条件 | 含义 |
|---|---|---|
| 队空 | `front == rear` | 当前没有数据结点 |
| 队满 | `front == rear->next` | 当前已分配空间中的空闲结点已用尽，需要扩充 |

这里的“满”不是说结构不能再入队，而是说**当前已分配的循环链表空间已经用完**；此时应再增添新的空闲结点。

### （3）
本问承接第（2）问的初始化状态来分析。

初始时只有 1 个空闲结点，且：

- `front == rear`
- 又因为是单结点循环，所以 `rear->next == rear`

于是有：

$$front == rear->next$$

这说明第一次入队时，先满足“队满”条件，因此要先在 `rear` 后插入一个新的空闲结点，再把元素写入原来 `rear` 所指的结点，最后令 `rear` 后移。

所以，第一个元素入队后：

**图解：首次入队后的状态**

关注原空闲结点变为数据结点，rear 后移到新的空闲结点。

![首次入队后的状态](/data/enhanced-analysis/assets/2019/42/original-analysis-2.svg)

- 原来的那个空闲结点变成了数据结点，存放第一个元素；
- 新插入的结点作为空闲结点；
- `front` 指向第一个元素所在结点；
- `rear` 指向那个新的空闲结点。

因此，此时循环链表中有 2 个结点：

- 1 个是有效数据结点；
- 1 个是预留空闲结点。

这与题目要求“出队空间可复用、整体空间只增不减”的设计是统一的。

### （4）
在前面状态定义的基础上，入队和出队过程如下。

#### 入队
设待入队元素为 `x`。

1. 先判断当前已分配空间是否已满，即是否满足 `front == rear->next`；
2. 若满，则在 `rear` 后插入一个新的空闲结点；
3. 将元素 `x` 存入 `rear` 当前所指结点；
4. 令 `rear = rear->next`，使 `rear` 继续指向下一空闲结点。

可写成过程化表述：

- 若 `front == rear->next`，则在 `rear` 之后增加一个新的空闲结点；
- 将入队元素保存到 `rear` 所指结点中；
- `rear = rear->next`。

整个过程只涉及一次判定、至多一次插入、一次赋值和一次指针移动，所以时间复杂度为 $O(1)$。

#### 出队
设出队元素为 `e`。

1. 先判断队空，即 `front == rear`；
2. 若队空，则出队失败；
3. 否则取出 `front` 所指结点中的元素；
4. 令 `front = front->next`。

注意这里**不释放结点**，只是让 `front` 后移。这样，被出队元素原来所在的结点就转为空闲结点，后续入队时仍可复用，从而满足“整个队列占用空间只增不减”。

出队同样只涉及常数次操作，时间复杂度也是 $O(1)$。

## 易错点

1. **误选顺序存储结构**  
题目要求入队时允许扩充，且入队、出队时间复杂度始终为 $O(1)$。顺序存储的扩容通常不能保证“始终”是 $O(1)$，因此不合题意。

2. **把出队理解为释放结点**  
本题明确要求出队后空间可重复使用，且整体空间只增不减，所以出队时不能释放结点，只能移动 `front`。

3. **忽略“牺牲一个空闲结点”这一设计**  
本题的判空、判满条件建立在“始终保留一个空闲结点”的循环结构上，因此初始时不是零结点，而是**一个空闲结点**。

4. **第一次入队时直接写入而不先扩充**  
按本题给定判满条件 `front == rear->next`，初始单结点循环时就满足该条件，所以第一次入队前要先插入一个新的空闲结点，再完成写入。
