## 答案

**B. 中断处理程序。**  
本地用户通过键盘输入时，键盘作为 I/O 设备会先向 CPU 发出中断请求，CPU 响应后执行对应的中断处理程序，因此最先获得键盘输入信息的是中断处理程序。

## 解析

题干问的是“首先获得键盘输入信息的程序”。关键词是“首先获得”。

键盘属于典型的中断式 I/O 设备。用户按下按键后，并不是命令解释程序、系统调用服务程序或用户登录程序先直接去“拿到”这个字符，而是先发生如下过程：

1. 用户按下键盘按键，键盘控制器产生输入事件。
2. 键盘设备向 CPU 发送中断信号。
3. CPU 响应中断，并根据中断信号查询中断向量表。
4. CPU 转去执行相应的中断处理程序。
5. 中断处理程序从键盘相关硬件或缓冲中读取输入信息，并将其交给系统后续环节处理。

因此，从“处理先后次序”看，最先接触并获得这次键盘输入信息的是**中断处理程序**。

题干中的“本地用户通过键盘登录系统”只是应用场景，核心仍然是在考查键盘输入的 I/O 响应流程。登录程序、命令解释程序都属于后续使用输入数据的上层程序，不是最先获得输入的程序。

## 选项分析

**A. 命令解释程序**  
错误。命令解释程序是在系统已经得到用户输入内容之后，才对命令进行解释和处理。它不是键盘输入到达系统后的第一接收者。

**B. 中断处理程序**  
正确。键盘输入采用中断方式时，CPU 先响应中断，再执行中断处理程序，由该程序首先读取并获得输入字符。

**C. 系统调用服务程序**  
错误。系统调用是用户进程主动请求操作系统服务的接口，而键盘按键输入首先触发的是硬件中断，不是用户进程发起系统调用。

**D. 用户登录程序**  
错误。用户登录程序需要依赖系统已经接收到键盘输入后，才能进一步进行用户名、口令等处理，因此它也不是首先获得输入信息的程序。

## 易错点

**“最先获得”与“最终使用”不要混淆。**  
登录程序、Shell 或其他应用程序可能最终使用键盘输入，但最先从硬件输入流程中接收该信息的是中断处理程序。

**中断与系统调用不要混淆。**  
键盘输入属于外设触发的**中断**事件；系统调用则是程序主动陷入内核请求服务，两者触发来源不同。

**题目考的是 I/O 输入路径的先后顺序。**  
对键盘输入而言，正确顺序应理解为：  
键盘设备 → 中断信号 → CPU 响应 → 中断处理程序 → 上层程序（如登录程序、命令解释程序等）。
