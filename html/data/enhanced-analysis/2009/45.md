## 答案

设 4 个信号量：

- `mutex = 1`：缓冲区互斥访问信号量；
- `empty = N`：缓冲区中空单元数；
- `odd = 0`：缓冲区中可供 `P2` 取走的奇数个数；
- `even = 0`：缓冲区中可供 `P3` 取走的偶数个数。

伪代码如下：

```c
semaphore mutex = 1;
semaphore empty = N;
semaphore odd = 0;
semaphore even = 0;

P1() {
    while (true) {
        x = produce();      // 生成一个正整数
        P(empty);           // 等待空单元
        P(mutex);           // 进入缓冲区临界区
        put(x);             // 将 x 放入缓冲区
        V(mutex);           // 离开临界区
        if (x % 2 == 0)
            V(even);        // 通知 P3 有一个偶数可取
        else
            V(odd);         // 通知 P2 有一个奇数可取
    }
}

P2() {
    while (true) {
        P(odd);             // 等待奇数
        P(mutex);           // 进入缓冲区临界区
        getodd();           // 取出一个奇数
        V(mutex);           // 离开临界区
        V(empty);           // 释放一个空单元
        countodd();         // 统计奇数个数
    }
}

P3() {
    while (true) {
        P(even);            // 等待偶数
        P(mutex);           // 进入缓冲区临界区
        geteven();          // 取出一个偶数
        V(mutex);           // 离开临界区
        V(empty);           // 释放一个空单元
        counteven();        // 统计偶数个数
    }
}
```

## 解析

### 信号量设置与含义

本题是生产者—消费者问题的变形，但消费者按数据奇偶性分工：

- `P1` 负责生产数据并放入缓冲区；
- `P2` 只取奇数；
- `P3` 只取偶数。

因此需要解决两类约束：

1. **互斥访问缓冲区**  
   缓冲区是共享资源，`put()`、`getodd()`、`geteven()` 不能并发执行，所以设置互斥信号量 `mutex`，初值为 1。

2. **同步关系**  
   - 生产者放入数据前，必须保证缓冲区有空单元，所以设置 `empty`，初值为 `N`。
   - `P2` 只能在缓冲区中存在奇数时才能取数，所以设置 `odd`，初值为 0。
   - `P3` 只能在缓冲区中存在偶数时才能取数，所以设置 `even`，初值为 0。

### 三个进程的同步与互斥实现

`P1` 每次先执行 `produce()` 生成一个正整数 `x`。在把 `x` 放入缓冲区之前，先执行 `P(empty)`，表示申请一个空单元；再执行 `P(mutex)` 进入临界区，完成 `put(x)` 后执行 `V(mutex)` 退出临界区。

随后，`P1` 还要根据 `x` 的奇偶性发出对应的同步信号：

- 若 `x` 为偶数，则执行 `V(even)`，唤醒 `P3`；
- 若 `x` 为奇数，则执行 `V(odd)`，唤醒 `P2`。

`P2` 只处理奇数，因此必须先执行 `P(odd)`，只有在确实存在奇数时才允许继续。之后执行 `P(mutex)` 进入临界区，从缓冲区取出一个奇数 `getodd()`，再执行 `V(mutex)` 退出临界区。取走一个数据后，缓冲区增加了一个空单元，因此执行 `V(empty)`。最后调用 `countodd()` 统计奇数个数。

`P3` 与 `P2` 的过程完全对应，只是它等待的是 `even`，取走的是偶数 `geteven()`，最后执行 `counteven()`。

### 执行顺序说明

各进程中 `P`、`V` 操作的顺序不能颠倒：

- 访问缓冲区前必须先申请资源，即先执行 `P(empty)` 或 `P(odd)`、`P(even)`，再执行 `P(mutex)`；
- 完成缓冲区操作后，应先释放互斥信号量 `mutex`，再释放相应的同步资源；
- `P1` 放入的数据是奇数还是偶数，决定了应该唤醒哪个消费者，因此必须分别对 `odd` 或 `even` 执行 `V` 操作，不能混用。

## 易错点

- 只按普通生产者—消费者问题处理，遗漏 `odd` 和 `even` 两个按类型同步的信号量。
- 忘记对缓冲区访问加互斥，导致 `put()`、`getodd()`、`geteven()` 可能并发进入临界区。
- 将 `empty` 初值写错。缓冲区共有 `N` 个单元，因此初值应为 `N`。
- `P1` 生产后没有按奇偶性分别执行 `V(odd)` 或 `V(even)`，从而无法保证 `P2` 只取奇数、`P3` 只取偶数。
