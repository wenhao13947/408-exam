## 答案

A：`01111100 00111110 10`

理由：HDLC 采用比特填充实现透明传输，数据中每出现连续 `5` 个 `1`，就在其后插入 `0`。题干给出的比特串中恰好出现两次这种情况，填充后得到 A。

## 解析

HDLC 帧的首尾标志字段为：

$$01111110$$

为了避免数据部分中也出现与标志字段相同的特征位型，HDLC 在发送时采用比特填充规则：

- 发送端：数据中每出现连续 `5` 个 `1`，就在后面插入一个 `0`
- 接收端：若检测到连续 `5` 个 `1` 后面跟着一个 `0`，则删去这个 `0`

本题给出的原比特串为：

$$01111100\ 01111110$$

按顺序检查其中连续 `1` 的情况：

第一段 `01111100` 中，存在一组连续 `5` 个 `1``（11111）`，因此应在其后插入 `0`：

$$01111100 
\rightarrow 011111000$$

继续看第二段 `01111110`，其中前 `5` 个 `1` 仍构成连续 `5` 个 `1`，因此也要在第 `5` 个 `1` 后插入 `0`：

$$01111110 
\rightarrow 0011111010 \text{（与前一段拼接后整体表现为题目选项格式）}$$

因此整个组帧后对应的发送比特串为：

$$01111100\ 00111110\ 10$$

这与 A 完全一致。

## 选项分析

A：`01111100 00111110 10`  
正确。对原串按 HDLC 的比特填充规则处理后，恰好得到该结果。

B：`01111100 01111101 01111110`  
错误。该结果没有正确体现“连续 `5` 个 `1` 后插入 `0`”的规则，且末尾仍保留了会造成歧义的 `01111110` 形式，不符合题意。

C：`01111100 01111101 0`  
错误。填充结果不完整，且插入位置与连续 `5` 个 `1` 的判定不对应。

D：`01111100 01111110 01111101`  
错误。该选项基本保留了原有 `01111110` 结构，没有正确进行比特填充，不能作为组帧后上信道传输的比特串。

## 易错点

- 不要把 `01111110` 直接当作普通数据照搬输出。只要数据部分出现连续 `5` 个 `1`，就必须插入 `0`。
- 比特填充是“遇到 `11111` 就填 `0`”，不是遇到 `6` 个 `1` 才处理。
- 本题问的是“组帧后对应的比特串”，即发送到信道上的结果，应写填充后的串，而不是原始数据串。
