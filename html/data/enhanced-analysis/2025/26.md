## 答案

**B．6 次。**  
理由：采用 **固定分配、局部置换** 且使用 **LRU** 算法时，只能在该进程已有的 3 个页框中按“最近最久未使用”原则进行替换。按访问序列逐步模拟后，共发生 **6 次缺页**，因此缺页异常处理程序也执行 **6 次**。

## 解析

题干给出：

- 已分配 **3 个页框**
- 初始已在内存中的页面为 `{0,1,2}`
- 页面访问序列为  
  `{0,1,2,0,5,1,4,3,0,2,3,2,0}`

“固定分配”表示该进程自始至终只有这 3 个页框；  
“局部置换”表示发生缺页时，只能从这 3 个页框中的页面里选一个淘汰，不能动其他进程的页框。  
LRU 的判断标准是：**淘汰最近最长时间没有被访问的页面**。

按序列模拟如下：

| 访问页面 | 是否缺页 | 淘汰页面 | 访问后页框内容（按 LRU 新旧关系理解） |
|---|---|---|---|
| 初始 | - | - | `{0,1,2}` |
| 0 | 否 | - | `{1,2,0}` |
| 1 | 否 | - | `{2,0,1}` |
| 2 | 否 | - | `{0,1,2}` |
| 0 | 否 | - | `{1,2,0}` |
| 5 | 是 | 1 | `{2,0,5}` |
| 1 | 是 | 2 | `{0,5,1}` |
| 4 | 是 | 0 | `{5,1,4}` |
| 3 | 是 | 5 | `{1,4,3}` |
| 0 | 是 | 1 | `{4,3,0}` |
| 2 | 是 | 4 | `{3,0,2}` |
| 3 | 否 | - | `{0,2,3}` |
| 2 | 否 | - | `{0,3,2}` |
| 0 | 否 | - | `{3,2,0}` |

因此，发生缺页的位置是访问：

$5,\ 1,\ 4,\ 3,\ 0,\ 2$

共计

$$6$$

次缺页，所以正确答案为 **B**。

### 关键判断说明

以第一次缺页为例：访问到页面 `5` 时，当前内存中是 `0,1,2`。  
回看此前最近的访问次序：

- `0` 刚刚访问过
- `2` 比 `0` 更早访问
- `1` 最久没有访问

因此淘汰 `1`，换入 `5`。

再如访问页面 `1` 时，当前页框中是 `2,0,5`。其中：

- `5` 是刚访问过的新页
- `0` 比较近才访问
- `2` 更久未使用

因此淘汰 `2`，换入 `1`。

后续各步都按同一原则处理即可。

## 选项分析

A．**5**  
错误。按完整序列模拟，缺页一共是 6 次，不是 5 次。

B．**6**  
正确。严格按 LRU 置换过程统计，恰好发生 6 次缺页。

C．**7**  
错误。比实际结果多算 1 次，通常是把某次命中误判成缺页，或在 LRU 次序更新时出错。

D．**8**  
错误。与逐步模拟结果不符，明显高于实际缺页次数。

## 易错点

- **不要把初始装入的 `{0,1,2}` 再计为缺页次数。**  
  题干已经说明这 3 页“已调入内存”，统计应从后续访问开始。

- **LRU 看的是“最近最久未使用”**，不是页号大小，也不是最早进入内存的页面。  
  进入内存早，不一定先被淘汰；关键看“最近一次被访问”的时间。

- **命中后也要更新 LRU 次序。**  
  例如前面连续访问 `0,1,2,0`，最后一次访问 `0` 会改变后续第一次置换时的淘汰对象；如果忽略这一点，后面结果会全部错位。
