## 答案

**B. 主存地址**

理由：在中断 I/O 方式下，CPU 与打印控制接口中的 I/O 端口之间交换的通常是数据、状态和控制信息；**主存地址**不属于这一路径上直接交换的信息，设备也不会像 DMA 那样根据主存地址自行去内存取数。

## 解析

题干问的是：**采用中断 I/O 方式控制打印输出时，CPU 和打印控制接口中的 I/O 端口之间，不可能交换什么信息。**

解题关键是把“交换双方”看准：这里不是“CPU、主存、打印机整个系统之间会涉及什么”，而是**CPU 与 I/O 端口之间直接传递什么信息**。

在中断 I/O 方式下，打印输出的一般过程是：

1. CPU 从程序和主存中取得待打印的数据。
2. CPU 通过 I/O 指令把字符送到打印控制接口的数据端口。
3. CPU 或设备通过状态端口/中断机制反映设备是否就绪、是否忙、是否完成。
4. CPU 还可以通过控制端口发出启动、复位等控制命令。

因此，CPU 与 I/O 端口之间直接交换的信息，常见有三类：

- **数据**：例如待打印字符；
- **状态**：例如忙、就绪、完成、出错；
- **控制命令**：例如启动打印、复位等。

而**主存地址**不属于这里的直接交换内容。因为在中断 I/O 方式中，数据搬运的主体仍是 **CPU**：CPU 先从主存取出数据，再写入 I/O 端口。  
如果是把**主存地址**交给设备控制器，由设备自行按地址到主存取数，这对应的是 **DMA** 的典型特征，而不是中断 I/O 方式。

所以，不可能交换的信息是 **B. 主存地址**。

## 选项分析

**A. 打印字符**：可能交换。  
打印机要输出具体内容，CPU 必须把待打印的字符经 I/O 端口送给打印控制接口，因此这是典型的交换信息。

**B. 主存地址**：不可能交换。  
中断 I/O 方式下，CPU 负责在主存和 I/O 端口之间搬运数据，控制接口并不需要从 CPU 这里接收主存地址再自己去访存；这类按主存地址直接访问内存的方式属于 DMA 思路。

**C. 设备状态**：可能交换。  
CPU 需要知道打印机当前是否忙、是否空闲、是否完成、是否出错，因此会从 I/O 端口读取设备状态信息。

**D. 控制命令**：可能交换。  
CPU 可以向打印控制接口发送控制命令，例如启动、停止、复位等，所以这类信息也可能交换。

## 易错点

- 容易把“系统中涉及过主存”误判为“CPU 和 I/O 端口之间会交换主存地址”。这里问的是**直接交换的信息类型**，不是整个打印过程涉及哪些部件。
- 要区分 **中断 I/O** 和 **DMA**：
  - **中断 I/O**：CPU 负责数据搬运；
  - **DMA**：设备控制器可依据主存地址直接与主存交换数据。
- 看到“打印输出”不要只想到“字符数据”，状态信息和控制命令同样是 I/O 端口常见的交换内容。
