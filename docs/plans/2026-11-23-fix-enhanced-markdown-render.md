# 修复增强解析中 Markdown 表格与公式不渲染的问题（2026-11-23）

> 状态：已完成实施并通过浏览器验证（2026-11-23）。

## 1. 目的与背景

打开 `408刷题原型.html#/y/2009/q/2`，进入「查看答案与解析」→「增强解析」后，看到的表格是原始 Markdown 文本（`| 步骤 | 操作 | ...`、`|---|---|---|`），`$$ ... $$` 公式也原样显示，没有渲染成表格和数学公式。

根因定位（已通过读取源码和数据文件确认，不是浏览器或数据缺失问题）：

1. 页面使用的是 `408刷题原型.html` 里手写的轻量函数 `mdToHtml()`（第 258–298 行）。它只支持：标题 `#`、引用 `>`、列表 `- / 1.`、水平线 `---`、代码块 ```、普通段落、行内 `**粗体**` / `*斜体*` / `` `代码` ``。**它没有实现 Markdown 表格（GFM pipe table）语法**，所以 `| ... |` 被当成普通段落原样输出。
2. 多行公式 `$$\n\max = 3\n$$` 被 `mdToHtml()` 当成普通段落，并且用 `<br>` 把三行拼在一起，变成 `$$<br>\max = 3<br>$$`。随后 `tex()` 调用 KaTeX 的 `renderMathInElement`，但 KaTeX 只能匹配同一个文本节点内的 `$$...$$`；`<br>` 把文本切成了多个节点，匹配失败，所以公式也原样显示。
3. KaTeX 本地文件（`html/vendor/katex/`）存在且脚本已引入，函数 `tex(box)` 也确实被调用，因此不需要新增或修复 KaTeX 依赖。

### 追加问题：题干 SVG 溢出卡片（用户于 2026-11-23 追加，已确认一起处理）

打开 `#/y/2009/q/47` 时，题干中的网络拓扑图和路由表图溢出白色卡片右侧。原因：

1. 题干 HTML 中有 3 个内联 `<svg>`（draw.io 导出），其中两个主图分别带固定属性 `width="852"` 和 `width="721"`。
2. 页面容器 `#app` 最大宽度 520px，卡片内可用宽度约 484px。
3. 现有 CSS 只有 `.stem img { max-width: 100%; height: auto; }`，只约束 `<img>`，不约束 `<svg>`。
4. SVG 外层 `.svg-wrapper` / `.svg-container` 的样式来自原网页但未随数据搬入本项目，因此没有任何宽度限制。

修复：补 `.stem svg { max-width: 100%; height: auto; }` 与 `.stem .svg-wrapper { overflow-x: auto; }`。不改数据文件。

## 3. 核心逻辑

`mdToHtml()` 是一个「逐行扫描 + 分支输出 HTML」的转换器。修复只需在扫描循环里增加两个分支，并把它们放在「普通段落」分支之前（否则会被段落逻辑吃掉）：

```mermaid
flowchart TD
    A[读取一行 Markdown] --> B{代码块 ``` ?}
    B -- 是 --> C[收集到 </code></pre>]
    B -- 否 --> D{标题 # / 引用 > / 列表 - ?}
    D -- 是 --> E[按对应规则输出 HTML]
    D -- 否 --> F{【新增】表格首行 + 分隔行 ?}
    F -- 是 --> G[逐行拆分单元格<br>输出 table/thead/tbody]
    F -- 否 --> H{【新增】独立一行 $$ 或 \[ ?}
    H -- 是 --> I[原样收集到结束符<br>输出完整 $$...$$ 文本块]
    H -- 否 --> J[普通段落：空行分段，行内转 HTML]
    C --> A
    E --> A
    G --> A
    I --> A
    J --> A
    A --> K[输出 HTML 交给 tex 渲染公式]
```

关键点：

- **表格识别**：当前行含 `|`，且下一行是分隔行（如 `|---|---|---|---|`，用正则判断「由 `|`、`:`、`-`、空格组成且至少含一个 `-{3,}`」）时，才认定为表格，避免把普通句子里的竖线误判成表格。
- **单元格拆分**：去掉行首/行尾的 `|` 后按 `|` 拆分，对每个单元格调用已有的 `inline()`，因此 `` `a` `` 仍会变成 `<code>a</code>`。
- **公式块识别**：当某行 trim 后正好是 `$$`（或 `\[`）时，一直收集到下一行正好是 `$$`（或 `\]`），把整段原样放进一个 `<p>`，**不插入 `<br>`、不做转义**，保证 KaTeX 能在同一文本节点里匹配分隔符。同一行的 `$$ ... $$` 保持原逻辑即可。
- **顺序很重要**：表格分支、公式块分支必须放在 `while` 循环末尾的「普通段落收集」之前。

## 6. 潜在风险

1. **误判表格**：普通文本中恰好出现 `|` 且下一行是 `---` 时可能被误判。通过「必须同时满足含 `|` + 下一行是分隔行」降低风险；数据文件中未发现此类情况。
2. **未转义竖线**：Markdown 表格里若单元格含 `\|`，简单拆分会把一个单元格拆成两个。当前数据未使用该写法；如需兼容，可在拆分前用占位符保护 `\|`。
3. **KaTeX 特殊字符**：公式块原样输出（不 HTML 转义），若公式中含 `<`、`&` 可能被浏览器当作标签。当前题库公式使用 `\to`、`\max`、`\frac` 等命令，不含裸 `<`；保持与现有行内公式一致的处理方式。
4. **窄屏溢出**：表格最宽 4 列，已用 `table-wrap` + `min-width` 处理横向滚动。
