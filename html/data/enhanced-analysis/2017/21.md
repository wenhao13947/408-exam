## 答案

**D. 通用寄存器和 I/O 端口之间。**

理由：I/O 指令是由 CPU 发出的，CPU 不能直接与 I/O 设备本体完成这类数据传送，而是通过设备控制器中的 **I/O 端口**，在 **CPU 的通用寄存器** 与 **I/O 端口** 之间交换数据。

## 解析

题干问的是：**I/O 指令实现的数据传送通常发生在什么对象之间**。

判断本题的关键是区分两个层次：

1. **设备层次**
   I/O 设备本身是外设，如键盘、磁盘、打印机等。

2. **CPU 可直接打交道的层次**
   CPU 发出 I/O 指令时，并不是直接对外设本体读写，而是先访问设备控制器中的寄存器。这些寄存器通常称为 **I/O 端口**。

也就是说，CPU 执行 I/O 指令时，实际完成的是：
- 从某个 I/O 端口读入数据到 CPU 的通用寄存器；
- 或者把 CPU 通用寄存器中的数据写出到某个 I/O 端口。

因此，**I/O 指令所对应的“数据传送双方”通常是通用寄存器和 I/O 端口**，而不是通用寄存器直接对 I/O 设备，也不是 I/O 设备直接对 I/O 端口作为题干所问的指令传送对象。

标准教材中的表述也一致：CPU 通过地址总线选中某个 I/O 端口，通过数据总线在 **CPU 寄存器** 与 **I/O 端口** 之间传送数据，所以答案应选 **D**。

## 选项分析

**A. I/O 设备和 I/O 端口之间**

错误。  
I/O 设备与设备控制器之间当然存在信息交换，但题干问的是 **I/O 指令实现的数据传送通常发生在什么之间**。从 CPU 执行指令的角度看，I/O 指令直接操作的是 **I/O 端口**，而不是把“I/O 设备和 I/O 端口之间”作为该指令的数据传送对象来表述。

**B. 通用寄存器和 I/O 设备之间**

错误。  
这是最容易混淆的干扰项。CPU 不能直接跨过设备控制器去和外设本体进行 I/O 指令级的数据传送，必须经过 **I/O 接口/设备控制器**。因此不是“通用寄存器和 I/O 设备之间”。

**C. I/O 端口和 I/O 端口之间**

错误。  
这不是 I/O 指令通常描述的数据传送方式。常见 I/O 指令的核心是 CPU 寄存器与某个端口之间的输入或输出，而不是端口之间互传。

**D. 通用寄存器和 I/O 端口之间**

正确。  
I/O 指令本质上就是在 **CPU 通用寄存器** 与 **I/O 端口** 之间进行数据传送，完全符合题意。

## 易错点

**易错点 1：把“外设”和“端口”混为一谈**  
外设是设备本体，端口是 CPU 访问设备时所通过的接口寄存器。考试问 I/O 指令时，通常应优先想到 **CPU 寄存器 - I/O 端口** 这一对。

**易错点 2：看到“输入/输出”就误判为与设备直接传送**  
“输入到计算机”或“输出到设备”是功能层面的说法；落实到指令执行层面，CPU 实际访问的是 **I/O 端口**，不是直接访问设备本体。

**检查方法**  
遇到此类题时，先问自己一句：**CPU 这条指令到底能直接操作谁？**  
答案通常是：**寄存器、主存、I/O 端口**；而不是直接操作外设本体。
