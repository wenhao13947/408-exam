## 答案

### （1）
PCB 位于**内核区**。执行 `scanf()` 等待键盘输入时，该进程处于**阻塞态**。

### （2）
`main()` 函数的代码位于**只读代码段（.text）**。其直接调用的函数中，功能需要通过执行驱动程序实现的是 **`scanf()`** 和 **`printf()`**。

### （3）
变量 `ptr` 本身被分配在**读/写数据段**。若变量 `length` 没有被分配在寄存器中，则被分配在**用户栈段**。`ptr` 指向的字符串位于**堆区**。

## 解析

### （1）
本问分别判断 PCB 所在区域和进程状态。

PCB 是操作系统为进程建立和维护的数据结构，用于记录进程状态、资源分配和调度信息，属于操作系统管理内容，因此位于**内核区**，不在用户进程的代码段、数据段、栈或堆中。

`scanf()` 的作用是从标准输入读入数据。题目明确说“等待键盘输入时”，此时进程还不能继续向下执行，必须等待 I/O 事件完成，所以该进程处于**阻塞态**。

### （2）
先看 `main()` 本身的位置。`main()` 是函数，其机器指令属于程序代码，因此位于**只读代码段（.text）**。如果结合题图阅读，可对应到存放程序指令的那一段。

再看 `main()` 直接调用了哪些函数：

| 直接调用的函数 | 作用 | 是否需要通过执行驱动程序实现功能 |
|---|---|---|
| `malloc()` | 动态申请内存 | 否 |
| `scanf()` | 输入字符串 | 是 |
| `strlen()` | 计算字符串长度 | 否 |
| `printf()` | 输出结果 | 是 |
| `free()` | 释放动态内存 | 否 |

其中：

- **`scanf()`**：需要从键盘等输入设备获取数据，属于 I/O 功能，实现时需要借助驱动程序。
- **`printf()`**：需要把结果输出到终端等输出设备，属于 I/O 功能，实现时需要借助驱动程序。
- **`malloc()`**：是内存分配函数，不是设备 I/O。
- **`strlen()`**：只是对内存中的字符串逐个字符统计长度，不涉及设备。
- **`free()`**：是内存释放函数，不是设备 I/O。

所以本问答案是：需要通过执行驱动程序实现功能的直接调用函数为 **`scanf()` 和 `printf()`**。

### （3）
本问要区分“变量本身在哪”和“变量指向的对象在哪”。

`char * ptr;` 定义在函数外，所以 `ptr` 是**全局变量**。题图采用的口径是把 `.bss` 与 `.data` 合并处理，因此这里答 **读/写数据段**。

`int length;` 定义在 `main()` 内，是**局部变量**。局部变量若未被编译器优化分配到寄存器中，通常存放在**用户栈段**。

执行
$$
ptr=(char*)malloc(100)
$$
后，系统动态申请一块 100B 的内存，并把首地址赋给 `ptr`。因此：

- `ptr` 自身仍在**读/写数据段**
- `ptr` 指向的那块 100B 空间在**堆区**

随后 `scanf("%s", ptr)` 把输入的字符串写入 `ptr` 指向的那片动态分配空间，所以字符串内容也位于**堆区**。

## 易错点

1. 不要把 **`ptr` 变量本身的位置** 和 **`ptr` 指向内容的位置** 混为一谈。  
`ptr` 是全局指针变量，在**读/写数据段**；它指向的字符串在 **堆区**。

2. `length` 是局部变量，但题目专门说明“若没有被分配在寄存器中”，这时才答 **用户栈段**。

3. 第（2）问问的是“其直接调用的哪些函数”，应在 `main()` 直接调用的函数里判断，答案按题目评分口径取 **`scanf()`、`printf()`**。
